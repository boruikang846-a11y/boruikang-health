## 产品经理：患者身份与数据关系

[打开身份关联演示](web/patient-identity-demo.html)。这是自带样式、脚本与虚构数据的单文件 HTML，可直接双击或单独发给产品经理离线讲解。

首页采用一屏一步的 7 幅图形画面：两路来源、医院资料导入、患者尚未建立联系入口、微信侧身份到达但未核验、假设核验后的平台关联、发送条件、待确认的业务安排。医院卡片持续标注“医院库里没有患者的微信号”；微信侧标识到达前，平台只有患者档案，没有对应联系人。关联记录只在平台内展示，医院记录保持原样。

演示默认停在前置缺口：患者尚未添加企微好友、关注公众号或主动进入小程序，不能由医院名单直接创建这些关系。打开说明或取消说明均不推进；只有选择“仅预览：假设患者已进入”才展示渠道标识。之后还有独立的身份核验假设门槛。三种入口分别保存演示前提，不能互相替代。小程序访问也不表示已关注公众号或添加企微。

即使假设已绑定，页面仍显示发送条件待确认、未发送消息。当前实现中，企微创建发送任务后需要成员确认；公众号发送受消息类型、交互窗口和接口权限等约束。患者引导人及场景、身份核验方式及凭据、真实通道接入仍需业务确认；不把假设预览描述成已跑通的运营流程。医院委托运营和真实数据同步也仍待确认，小程序患者服务待建设。

[数据字段与 7 个补充场景](web/patient-identity-reference.html) 保留原详细版，供被问到具体问题时查阅：首次绑定、重复同步、双通道、同号候选、家属代办、跨院编号、取消关注与解绑。该页明确这些场景以渠道关系成立、核验结果满足为教学假设，不代表前置业务已经落实；可返回动画首页。单独分享动画 HTML 可以演示全部 7 步，如需补充场景请同时携带 reference 文件。

演示以现有来源身份与人工绑定规则为依据，全部为虚构内存数据，不连接外部服务，不修改正式业务逻辑或数据库。小程序能力、结构化家属关系与查阅授权、体检与院内身份归并均明确为待设计或待建设。

以下保留历史原型开发记录；3.x 是探索稿编号，尚未实现的扫码入组、患者 H5、独立 AI 计划和质量中心不属于当前交付范围。旧记录的运行包、本地地址及未推送状态不是当前状态。

# HEALTH 1.8 离线交互原型

打开 [完整原型](web/interactive.html)。[原型入口](web/index.html)同时保留历史页面。

患者中心文件导入可直接打开[专项入口](web/admin/patient-file-import-1.8.html)，以虚构运营主管进入患者清单。点击“文件导入”，体验上传、校验与分配、导入结果；没有文件时可选虚构正确/重复或错误样例。实际 Excel/CSV 在本地读取，模板与校验复用现有业务页面；演示建档、首触任务、时间轴与清单联动仅保存在当前页面。

完整原型使用虚构患者、报告和业务记录，不请求后端或任何外部服务。侧栏、工作台队列、清单、详情、患者档案页签、流程总览和返回路径均可点击。浏览器后退可以回到上一页；切换演示角色保留记录，刷新或“重置演示”恢复初始状态。

主要验收路径：

1. 运营人员进入随访任务 2001，领取、关联原报告、保存草稿并提交审核。
2. 切换责任医生，打开原报告并确认已阅，在意见审核中通过或退回。退回原因必填。
3. 切换原运营人员，登记未接通时的原因与下次计划，或核实身份、对照报告后登记接通反馈；完成任务。
4. 切换责任医生，查收完成结果；查看同一患者的时间轴追溯这些动作。
5. 护士处理自己的患者和任务 2002；不能审核意见或关闭临床异常。医生档案只读，平台管理员不能访问患者。
6. 运营主管演示医院 Mock 幂等同步、筛查判定建档、补充虚构原报告、责任分派、邀约、预约到诊、服务激活、转诊、宣教草稿、医护账号与报告归档。筛查建档时选择责任医生、负责人并人工确认首次日期；补充报告后可继续完整随访。更换责任医生后，未联系任务的旧审核失效。
7. 从渠道或系统介绍进入公开介绍，查看三种规划模式；没有患者业务入口。

这是页面流程演示；演示角色入口不代表真实认证，演示保存不写数据库、发送消息或接通医院。节点日期与个体内容需人工核对，SOP 是团队系统外的业务流程。

需要单个文件时，用 Python 3 运行打包脚本，传入输出 HTML 路径。打包结果包含全部样式和脚本，可直接双击打开，无需 Java、Node.js 或 HTTP 服务。
