# HEALTH 1.6 离线交互原型

打开 [完整原型](web/interactive.html)。[原型入口](web/index.html)同时保留历史页面。

完整原型使用虚构患者、报告和业务记录，不请求后端或任何外部服务。侧栏、工作台队列、清单、详情、患者档案页签、流程总览和返回路径均可点击。浏览器后退可以回到上一页；切换演示角色保留记录，刷新或“重置演示”恢复初始状态。

主要验收路径：

1. 运营人员进入随访任务 2001，领取、关联原报告、保存草稿并提交审核。
2. 切换责任医生，打开原报告并确认已阅，在意见审核中通过或退回。退回原因必填。
3. 切换原运营人员，登记未接通时的原因与下次计划，或核实身份、对照报告后登记接通反馈；完成任务。
4. 切换责任医生，查收完成结果；查看同一患者的时间轴追溯这些动作。
5. 护士处理自己的患者和任务 2002；不能审核意见或关闭临床异常。医生档案只读，平台管理员不能访问患者。
6. 运营主管演示医院 Mock 幂等同步、筛查判定建档、补充虚构原报告、责任分派、邀约、预约到诊、服务激活、转诊、宣教草稿、医护账号与报告归档。筛查建档时选择责任医生、负责人并人工确认首次日期；补充报告后可继续完整随访。更换责任医生后，未联系任务的旧审核失效。
7. 从渠道或系统介绍进入公开介绍，查看三种规划模式；没有患者业务入口。

这是页面流程演示；演示角色入口不代表真实认证，演示保存不写数据库、发送消息或接通医院。节点日期与个体内容需人工核对，SOP 是团队系统外的业务流程。

需要单个文件时，用 Python 3 运行打包脚本，传入输出 HTML 路径。打包结果包含全部样式和脚本，可直接双击打开，无需 Java、Node.js 或 HTTP 服务。

```sh
python3 docs/demo-static/build-preview.py /tmp/health-prototype.html
```
