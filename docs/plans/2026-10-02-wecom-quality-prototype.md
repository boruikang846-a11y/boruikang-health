# 企业微信协作与质量保障原型 1.9

本轮先优化离线交互原型，保留 1.8 导入、医护权限及责任医生审核闭环，不接通外部服务。

## 页面与验收

- 运营、护士、医生：企业微信协作中心展示自己可访问的任务，链接至既有执行 / 审核 / 查收页面。
- 平台管理员：仅接入清单，不能看到患者任务。
- 运营主管、医生、平台管理员：质量保障中心包含发布门槛、测试矩阵、医学安全检查、缺陷闭环和 UAT。
- 运营人员与护士：不能直接打开质量中心。
- 模拟发送必须显示未接通与授权未验证的阻断；不会发送消息。
- 发布检查必须阻断，不能用目标指标或虚构缺陷作为真实质量证据。
- UAT 演示反馈仅存在当前页，刷新或离开丢失；不创建真实 GitHub Issue。

## 后续测试实现范围

Java 后端采用 JUnit / Spring 测试 / JaCoCo；pytest 用于独立 HTTP API 与外部契约集成测试。前端 Vitest + Testing Library，E2E Cypress。覆盖所有 Service 与 Controller，并建立端点清单防止遗漏。部署配置继续存放 boruikang-workflows。

后端行与分支覆盖率各 >80%；关键医学安全检查全部通过；适合自动化的测试用例自动化率 >90%；全套提交自动化反馈目标 <10 分钟，须由 CI 耗时证据验证。医学专家 review、UAT 和完整容量压测单独记录，不伪装为自动化达标。

性能建议基准待业务和环境校准：API P95 ≤500ms，100 并发错误率 <1%；数据库用代表性数据量、慢查询与执行计划制定独立基准。禁止把建议值显示成测量值。

医学安全：报告关联、责任医生本人审核、越权拒绝、正文版本与责任医生变更导致审核失效、异常本人处置、患者错绑与授权撤回阻断、隐私隔离、AI 草稿不自动诊断或调药。

患者端在现有项目中仅为介绍页。本轮没有新增患者业务；企业微信授权、患者反馈和撤回授权属于后续需要设计及实现的增量。

## 缺陷与验收

P0 医学伤害或隐私泄露，立即阻断；P1 关键流程或权限失效，发布前修复；P2 有替代路径，计划处理；P3 文案与外观。严重程度、优先级、负责人、复现证据、修复版本、回归证据和验收签署分别记录。医学相关缺陷需要专家复核。

本轮尚未创建 pytest / Vitest / Cypress 配置或 CI 部署流程；页面中的测试矩阵为下一阶段实施设计，非完成声明。
