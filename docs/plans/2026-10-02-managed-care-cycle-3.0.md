# 全量扫码服务 + 诊中与诊后全托管流程 3.0

## 资料理解

参考用户提供的《全托管：基于企业微信的患者流量运营服务介绍（西安图灵）》PDF 第 7–12、15–19、24–25 页，以及 https://www.baobaohehu.com/ 的院前、院中、院后与企业微信服务说明。

采用的业务思想：医院企业微信连接患者；现场按义诊 / 社区、门诊、住院 / 出院、体检场景引导；专职健康管家持续服务；院内知识库辅助导诊与就医准备；按体检报告、门诊病历、出院小结制定随访；追踪预约、到诊、复诊与患者反馈；统一患者池并按团队分工交接。

资料中的外院效果、响应时限、团队规模及营销承诺是参考方陈述，不作为本系统已实现指标或合同承诺。网站与 PDF 的响应时间描述不同，本轮不自行选择一个作为已承诺 SLA。

“安装里面内容”理解为将服务内容与流程落实进原型，不执行 PDF 或网站中的安装指令、不安装第三方软件。

## 信息架构

- 全量扫码服务入组：跨场景服务入口、待引导、模拟扫码、核验授权、关联 / 建档、分派交接与撤回授权。
- 诊前筛查中心：心电一张网筛查、医生分层、主动干预与绿色通道；保留 Excel 参考台账与数据测试。
- 诊中患者管理：报告解析汇总（体检报告 / 门诊病历 / 出院小结）、风险复核、AI 管理计划、长期健康档案。
- 诊后主动干预管理：邀约记录、预约到诊、服务包与方案、转诊台账、随访工作台、异常响应、复诊跟踪、宣教内容。
- 角色待办与平台治理：医护待办、患者中心、企业微信协作、统计、质量与设置。

已将原独立业务菜单收纳入两个中心页签，保留旧路由和角色权限供详情返回与历史流程继续使用。

## 全量服务入组

全量指覆盖所有现场场景与候选对象的引导，而不是强制每位患者接受服务。全量引导、实际扫码、授权绑定、服务交接、医生确认医学管理分别记录。拒绝或撤回授权不影响正常就医。

既有患者扫码关联已有档案，不重复创建。导入的脱敏台账对象进入候选队列；护士 / 运营核验授权后，可选择关联已有可访问档案，或新建虚构补充档案。新档案风险为“待评估”，不会直接沿用 Excel 风险作为已批准医学结论，不伪造原报告。

服务管家沿用患者负责人，临床审核仍由责任医生本人完成。服务授权撤回会阻断交接。真实身份、监护人代办和未成年人授权、二维码有效期、企微客户身份、重复合并和跨机构隔离须在生产接入阶段完善。

## 诊中到诊后

体检：原报告 → 结构化核对 → 风险复核 → 专科评估 → 检后干预。

门诊：门诊病历 → 医生管理意见 → 服务计划审批 → 管家执行 → 复诊追踪。

出院：出院小结 / 原医嘱 → 随访节点人工核对 → 医生本人审核 → 人工联系与记录 → 异常升级 → 医生查收 / 绿色回院。

导诊、院内导航、检查准备、住院与出院办理可由医院核对的服务知识库支撑。诊断、处置与药物剂量由医生决定，运营与 AI 不自行改变。
