# 诊前高危患者筛查中心实施方案

目标：按用户指定的七个子目录开发统计、预警、三类来源、高危患者和邀约记录；迁移既有回访跟踪表，保留数据、编辑和角色边界。

架构：正式 React 页面复用筛查判定、入组、文件导入和邀约接口，新增权限范围内统计与查询条件；HTML 原型复用既有内存记录和审计。患者整体风险与本次心电图分级分别保存，来源、入组和运营进度独立展示。参考截图用于目录与字段借鉴，不引入截图之外的卒中筛查、活动管理等一级功能。

技术：React 18、Ant Design 5、Java 21、Spring Boot、MyBatis、HTML/CSS/JavaScript。

1. 七个子目录在侧栏展开，默认统计；旧链接仍能回到对应记录。首次联系、预约、转诊保留为邀约页内办理入口。
2. 统计展示筛查记录数、待判定、高危及危急、已建档；来源分布、风险分布与工作清单都基于同一权限及日期范围，明确按记录而非去重人数统计。
3. 危急预警突出风险依据、处理状态与负责人；来源页提供日期、姓名、电话、证件尾号、风险、状态筛选和详情。健康筛查不根据指标自动作诊断。
4. 原型把“全周期管理 · 回访邀约跟踪表”移至邀约记录，保留三轮沟通、到诊、有效到诊、下次计划的直接编辑。正式端继续使用持久化邀约/预约台账，不把离线演示记录导入数据库。
5. 一张网分类按已登记分类筛选；体检导入指定 EXAM，健康筛查指定 HEALTH_SCREENING；缺失信息展示待补充。只导出现有权限与筛选结果。
6. 后端沿用 screening_record 数据表，增加查询 phone、id_card_tail、category、high_risk 条件及统计端点；新增本次心电图分级、适用范围、院方依据三个可空字段，提供独立 SQL 迁移；历史记录不自动回填指南等级。
7. 验证查询/统计权限、来源隔离、日期边界、名单与统计一致性、旧详情与编辑回归；构建 React 与离线 HTML，在浏览器检查七个页面、筛选、详情、导出和窄屏。

工作流：独立 codex/screening-center 分支；完成本地验证后提交、推送草稿 PR，不合并或部署。

指南补充：根据用户上传的《远程心电图危险分级诊断的中国专家共识》（2022），展示危急、预警、普通三级及各自就医指导，限定有效静息 12 导联适用范围与其他导联心律失常参照边界。未核实是资料状态，不是第四个临床等级；不按病种关键词自动分级，不以既有 SLA 代替指南的即刻要求。
