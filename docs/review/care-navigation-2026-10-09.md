# 诊前诊后导航整合验证

日期：2026-10-09。开发分支：`codex/care-navigation`。方案见 [流程导航设计](../feature/2026-10-09-care-navigation-design.md)。

本轮将运营主管侧栏收敛为 13 项，原患者池并入诊前、患者中心并入诊后，台账按环节进入。旧详情地址保留，显示菜单和路由授权分离；患者范围在阶段跳转、新建和详情返回间传递。

## 修复的具体问题

- 删除一级菜单会连带禁用旧详情链接：导航和权限拆开，旧地址进入归属中心。
- 患者档案换页签会清掉中心与患者参数：保留上下文，只替换档案页签。
- 环节复用全院列表容易混入其他患者：正式 API 查询传患者编号，原型共享台账按患者过滤。
- 复诊与首次到诊混称：默认以 `appointment_type=REVISIT` 展示复诊预约；正式端保留独立标明的历史“复诊与到诊任务”入口。
- 原型患者导入截止时间丢失时区导致本地显示偏移：生成本地日期时间，按 SLA 小时数核验。

## 已完成验证

- 管理端生产构建通过；生成物仅用于验证，不替代发布。
- 管理端 23 项导航、旧路由、角色权限、上下文和文件导入测试通过；患者范围与任务实际患者不一致时，运营及医生抽屉都阻断办理。
- 原型 7 套测试全部通过，覆盖菜单渲染、导航整合、患者导入、筛查详情、全旅程、三类诊后服务及患者服务演示。
- 独立审查验证越权患者、患者与任务不一致、详情返回、阶段上下文与首次到诊/复诊区分。
- 生成契约漂移检查通过：34 张表与 Mapper/Model、13 个旅程请求 DTO 及现有两条后端旅程路径保持同步。本轮不修改后端业务 API 或 SQL。
- CI 增加导航、诊后、筛查原型回归与管理端测试，合并前以实际 CI 结果为准。

## 验证边界与后续问题

本机浏览器工具拒绝 `file://` 预览，未完成浏览器视觉验收；正式 React 未连接真实后端执行登录和写入流程。离线演示全部是虚构内存数据。医院、微信、AI 的实际接通状态沿用原实现。

患者级共享台账尚不等于按就诊事件归档。下一步后端工作应优先统一预约任务语义，并在邀约、预约及转诊上完善可靠的旅程关联和历史数据处理；本轮没有假设或批量改写历史记录。原型里的体检个案和患者 H5 也不等于正式后端已实现相应新功能。

## 连续管理试点验收口径

原型中的验收说明归档于此，业务页面仅保留操作。

- 一例完整案例：签发、登记、核实、原报告、计划审核、执行反馈、医生查收、复诊证据及再次就诊；逐环节检查责任人、时间、来源、处理结果与后续动作。
- 连续入组队列：固定窗口内纳入全部符合条件患者，记录失访、撤回和无需复诊，分别统计有效联系、反馈闭环和核验到院。试点前确认分母、观察窗口、排除原因及证据来源；虚构样例不作为真实结果。
