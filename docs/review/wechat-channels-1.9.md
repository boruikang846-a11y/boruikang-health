# HEALTH 1.9 企业微信与公众号验收

日期：2026-10-04。范围：管理端接入企业微信与公众号（配置与连接测试、回调、联系人绑定、三类发送、来信待处理、活码、欢迎语、成员账号、档案页签与时间轴），以及用户端介绍页的微信互动演示。需求、HTML 原型、接口与设计、代码与 SQL 均锚定 1.9。

## 实现核对

- 接入配置保存不回显密钥；连接测试真实取凭证，结果与错误码入库；修改企业 ID / AppID、Secret 或通道类型后回到未验证。企业微信正式通道启用前必须有回调 Token 与 AESKey。
- 回调四个公开入口：通道未启用、缺回调凭证或签名不符返回 403 且不落数据；密文核对接收方；XML 拒绝 DTD；同一事件重复推送只记一次。
- 联系人由加好友、关注、扫码事件或手动同步生成，带来源渠道和添加成员；绑定、解绑在患者范围内人工完成并留痕；同步不解绑。
- 发送：公众号文字检查 48 小时互动与长度，模板消息逐行解析字段，企业微信创建群发任务并可刷新结果；已审核正文只取任务里责任医生通过的原文，页面传入的内容被忽略；未替换的 {占位} 被拒绝；相同请求键只发一次；失败保存微信返回的错误。发送不改变任务状态。
- 来信进入待处理，发送成功或标记后清零；已绑定患者的来信可转成咨询任务，一条来信只转一次。
- 医生只读自己患者的微信记录，不能发送；平台管理员只能配置，看不到联系人和消息；运营人员、护士只见待绑定联系人和自己患者的联系人。
- 模拟通道仅在 local、test、dev 可选，记录带标记，模拟与真实联系人不能混用通道。
- 用户端介绍页的互动演示是页面内固定脚本，没有新增接口。

## 尚未验证

- **真实微信接口**：没有医院的企业微信、公众号凭证，未向微信发起过任何真实请求。真实通道的可信 IP、模板审核、群发频次限制等要在拿到接入参数后联调。
- **MySQL**：本机没有 MySQL，新表、新列和种子只在 H2 上跑过；MySQL 上的建表、唯一约束与种子由 PR 的 CI 验证。
- **部署**：未改 Nginx 与 Jenkins。回调路径对公网开放的转发规则需要在 boruikang-workflows 另行交付。

本地验收仅使用 H2 虚构演示数据。发布走 workflows 仓现有 Jenkins dev-health-deploy，部署 develop，目标 both（共享 common 模块与两端前端都有变更）；发版为全量口径，须备份后清库重建。
