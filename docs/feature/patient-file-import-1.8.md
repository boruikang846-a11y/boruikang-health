# HEALTH 1.8 患者中心文件批量导入

版本：1.8，2026-10-01。用户补充要求 `/patients` 患者中心支持文件批量导入，与[患者池文件导入](screening-file-import-1.8.md)同次交付。

## 流程

```mermaid
flowchart LR
  A[患者中心 / 文件批量导入] --> B[下载 Excel 模板 / 选择 xlsx或csv]
  B --> C[逐行校验和预览]
  C --> D[选择责任医生、负责人、来源和患者类型]
  D --> E[确认导入]
  E --> F[事务建档 / 重复数据跳过]
  F --> G[批次新增和跳过结果 / 刷新患者中心]
```

通用文件格式、大小、编码、日期、500 行限制、预览与异步交互规则沿用患者池 1.8。患者中心直接创建患者档案，初始阶段 ENROLLED，风险 UNKNOWN；不得从文件自行推断风险或注册患者账号。

## 字段

必填列及值：姓名 `name`（80 字）、年龄 `age`（0–130 整数）、联系电话 `phone`（与新建患者约束一致）、科室 `department`（80 字）、病种/管理原因 `disease`（120 字）。性别 `gender` 可空，默认 UNKNOWN。

可选：来源编号 `external_id`（80 字）、证件号 `id_card`（15–18 位数字/X，沿用新建患者约束）、出生日期 `birth_date`（YYYY-MM-DD 或 Excel 日期）、住址 `address`（200 字）、紧急联系人 `emergency_contact`（80 字）、紧急联系电话 `emergency_phone`（24 字）、住院号 `inpatient_no`（60 字）、床号 `bed_no`（20 字）、内部备注 `note`（2000 字）。电话、证件号、住院号、来源编号等按文本保留前导零。

责任医生、负责人在弹窗统一选择且必填。主管可选择本院有效主管/运营/护士；运营和护士归属自己。患者类型、来源场景、来源机构在弹窗统一选择；可选择是否自动创建首次联系任务，默认开启，与人工建档一致。医生页面“我的患者”不显示导入按钮，接口也拒绝医生与平台管理员。

## 去重与结果

同医院已存在的证件号或文件来源编号跳过，不覆盖档案、不重分配、不重复创建首次联系任务。证件号比较统一为大写；来源编号限定文件来源 FILE_IMPORT，与真实医院接口来源分开。无来源编号时使用批次号与行序号作为来源键，保证同次提交重试不会重复写入；跨批次去重需填写来源编号或证件号。手机号可能属于家属，不作为合并依据。

后台统一校验全批，最多 500 行；合法数据在一个事务中写入。任一无效字段或非法分配整批拒绝、无部分写入。结果返回批次号、实际新增/跳过数量和逐条跳过原因，刷新当前患者列表。档案来源显示“文件导入”，每条建档及整个导入批次都追加审计。

## 验收

| 编号 | 结果 |
| --- | --- |
| P01 | 患者中心显示入口并可下载专属 Excel 空白模板，模板说明不误导入 |
| P02 | 文件字段严格校验并显示实际行号；缺必填、错误年龄日期、超限或损坏不能提交 |
| P03 | 同一批患者统一分配有效医生与负责人，档案字段及可选首触任务正确 |
| P04 | 文件内/库内重复来源编号或证件号跳过；同一批次重试不会重复建档或创建任务 |
| P05 | 运营/护士不能导入给其他人，医生/平台管理员不可导入，其他医院信息不泄露 |
| P06 | 全批事务、接口失败保留预览、关闭/重选清空、重复点击不重复提交 |

复用 patient.source_system/hospital_patient_id 与既有唯一索引，增加 FILE_IMPORT 来源值，无结构或迁移 SQL 变更。
