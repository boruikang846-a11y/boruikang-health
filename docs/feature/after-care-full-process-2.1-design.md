# 全流程诊后主动干预原型设计 2.1

日期：2026-10-09。依据：用户确认的三条服务路径及13张参考图。参考图用于梳理连续记录、人机协作与执行闭环，不作为医学规则、疗效保证或真实患者数据来源。

## 页面与服务路径

入口：[诊后主动干预](../demo-static/web/admin/index.html#/after-care)。工作台按门诊、住院与出院、体检检后三个场景切换。患者清单显示当前节点、计划状态、随访次数、主责团队；进入个案工作区查看全流程及待办。

- 门诊：门诊结束与病历医嘱核对 → 扫码入组与服务交接 → AI智能体生成诊后个案随访计划表 → 诊后个案计划审核 → 随访执行与医生反馈 → 复诊结果与服务结案。
- 住院：扫码入组接入与服务交接 → 住院服务及问题协调 → 出院小结与医嘱核对 → AI智能体生成诊后个案随访计划表 → 出院准备及管家交接 → 出院个案计划审核 → 居家随访与医生反馈 → 复诊结果与服务结案。
- 体检：体检结束与体检报告医嘱核对 → 扫码入组与服务交接 → AI智能体生成检后个案随访计划表 → 检后个案计划审核 → 随访执行与医生反馈 → 复诊结果与服务结案。

## 每个环节交付什么

| 环节 | 必要内容与完成依据 | 主责 |
| --- | --- | --- |
| 原报告与医嘱核对 | 本次事件、原报告ID及日期、医嘱核对结果、缺项与待确认内容；不复用另一就诊事件证据 | 责任医生 |
| 扫码入组与服务交接 | 身份核验、本人或家属授权、服务用途、来源渠道、负责人和医生、待办及交接结果；扫码不能自动完成绑定 | 管家 / 运营 / 护士 |
| 住院服务与问题协调 | 服务问题、需求、处理结果、未结事项及升级去向；临床问题转责任医生 | 管家协调，医生处理临床问题 |
| AI生成计划 | 已核对报告、医嘱、个人目标与待补资料；生成可编辑草稿，保存来源与版本 | 人工点击，AI辅助 |
| 出院准备及管家交接 | 出院资料、居家执行准备、复诊安排、联系渠道、家属需求及待办确认 | 服务负责人 |
| 计划审核 | 节点时间、内容、目标、升级规则；通过或退回意见、审核人、时间；修改后重新审核 | 责任医生本人 |
| 随访与反馈 | 联系时间及结果、症状及监测记录、医嘱依从性、患者困难、下一步动作；未接通记录重试 | 管家执行，医生查收 |
| 复诊与结案 | 实际复诊结果或医生确认的后续安排、最新随访查收、问题闭环、后续交接、患者确认及满意度状态 | 团队核验，医生提供医学结论 |

## 连续档案与个体计划表

个案围绕一次就医事件组织，长期档案关联多次个案，不因本轮结案删除。每条数据记录来源、采集时间和核实状态；缺失值不能按正常值处理。

| 档案类别 | 示例内容 | 作用 |
| --- | --- | --- |
| 医疗数据 | 病历、检验、影像、用药及医嘱 | 关联计划依据 |
| 监测数据 | 个人基线、指标、睡眠及设备记录 | 比较个人变化趋势 |
| 行为数据 | 饮食、运动、打卡与执行困难 | 评估可执行性与依从性 |
| 主观反馈 | 症状、不适、情绪、患者疑问 | 形成随访反馈与待处理事项 |

计划表目标字段：节点、日期或频次、个体问题、优先目标、具体动作、跟踪数据、效果评价标准、责任人、反馈方式、异常升级条件、复盘日期。当前功能原型已支持全部上述字段的逐节点审核填写；正式接口及持久化字段仍需后续实现。

首次随访建立基线；持续随访核实执行与变化；阶段复盘比较目标和实际结果；复诊节点核实诊疗结果和下一轮需求。每天提醒、每周复盘、每月调整是参考节奏，频次由责任医生结合个案确认，不能统一自动套用或宣称提醒已经发送。

## 风险识别与人机分工

AI辅助整理多源记录、发现待核实趋势、起草参考计划和汇总执行情况。识别线索包括偏离个人基线、持续变化和多个信号联动；具体医学阈值、优先级及处置由医生配置或确认，不从宣传图推导。

责任医生承担诊断、用药决策、风险判断、复杂病例处理与计划审核。运营与护士承担服务交接、联系、记录、问题协调和患者反馈核验。临床问题按接单、实质处理结果、患者获反馈核验闭环；已通知不能计为已关闭。

## 动态调整、留痕和结案

计划调整应关联新的患者反馈或医生意见。旧版本、审核意见、已执行记录保留；新草稿不得继承旧版审核。待审核版本不能用于联系患者；批准新计划后停用旧版未完成节点。当前HTML保存生成版本快照用于演示，正式端需关联既有计划与任务实现。

进入结案核验前，至少有有效随访、最新记录经责任医生查收、未结问题为零。结案记录复诊结果及后续安排；退出、失联、撤回授权不统计为正常服务完成。医生确认无需复诊需要独立医学依据。结案后转持续管理应新建服务周期并保留关联，不能将服务无限延期而无交接记录。

审计字段：患者、事件、报告、计划版本、动作、操作者、角色、时间、结果与依据。患者端只读本人服务摘要和已允许公开的反馈，不展示AI未审草稿、后台医学全文或内部备注。

## 原型与正式实现边界

此页面使用虚构内存数据，AI生成和扫码为本地模拟，不请求医院、企微或LLM，不自动发消息。完整个案工作区和H5双端原型使用独立演示状态。正式端复用既有旅程、任务、工单、报告和审计，不增加第二套业务状态机；体检场景与新增节点须同步更新契约、API与SQL迁移。

验证范围：三条完整流程、审核退回、医生本人权限、未查收阻断、临床问题升级与反馈核验、HTML转义、既有旅程/H5回归。脚本验证不替代浏览器视觉验收、真实接口联调或患者授权认证。
