# 诊前高危患者筛查中心 · 台账详情

更新日期：2026-10-09。

## 功能需求

回访邀约清单中的以下四列支持点击打开当前患者的详情弹窗，关闭后保留当前列表筛选与分页。键盘可聚焦并打开入口。

| 列 | 详情内容 |
| --- | --- |
| 三轮沟通 | 建立信任、持续跟进、关怀反馈三轮；每轮显示时间、结果、事实记录、负责人及下次计划；未记录时明确提示 |
| 预约 / 到诊 | 预约日期、预约科室、到诊状态、到诊日期；缺失字段显示未填写 |
| 有效到诊 / 原因 | 是否有效到诊、判定依据、未到诊原因；已到院但接诊记录待核实与有效到诊分别展示 |
| 下次随访 / 超期 | 下次时间、随访计划、执行负责人、当前计划状态及历史台账超期状态；按浏览器本地日期判断计划日是否已过 |

## 初始化与权限

为现有 64 条台账记录补充虚构详情，保留原表的历史填写完整性与汇总核对数据。演示详情使用独立字段，明确提示日期、正文和到诊依据为虚构。新导入记录未填写详情时展示缺失提示，不根据真实导入内容生成虚构就诊凭据。新增沟通后同步更新对应轮次的详情，下次联系时间同步到随访详情。

详情沿用列表中的可见患者范围；用户无权查看的患者不能通过详情入口访问。查看详情不要求运营编辑权限，登记或修改沿用现有角色规则。

## 验收标准

1. 四列各自点击可展示所选对象对应详情；运营主管、运营人员、护士打开详情后即可直接编辑，医生保持只读。
2. 64 条演示记录可查看虚构详情；未填、未到诊、已到诊、有效与无效到诊均有明确提示。
3. 新增沟通后弹窗显示最新正文及下次计划，原始映射数据不被改写。
4. 超期与未超期根据当前演示计划日期展示，历史状态单独标注。
5. 关闭弹窗保留筛选和分页；越权对象不可读取。

原型入口：[筛查中心](../demo-static/web/interactive.html#/screening)。验证脚本：`docs/demo-static/tests/screening-details.test.cjs`。

当前交付是 HTML 交互原型与功能需求；数据仅保存在页面内存，刷新恢复初始化。正式 React、Java API 和数据库持久化待按本需求实现。

## 详情编辑增量（2026-10-09）

详情弹窗直接显示预填表单，三轮沟通按三张卡片展示，无需再次切换编辑模式。底部提供“保存修改”和“取消”。三轮沟通分别编辑时间、结果、正文、负责人、下次联系时间；预约到诊编辑预约日期、科室 / 医生、到诊状态与日期；有效到诊编辑是否有效、判定依据、未到诊原因；随访编辑下次时间与计划。随访执行负责人沿用分配结果，历史超期状态保持只读，当前超期自动计算。

保存前必须填写修改原因。已记录的沟通须有时间、正文和负责人，未接通须有下次联系时间。已到诊须填到诊日期，未到诊不能填到诊日期；改为未到诊时同步取消有效到诊。有效到诊须已有到诊日期及依据；未到诊须填原因。随访时间与计划同时填写或同时清空。

保存后列表、详情弹窗和患者档案同步显示，当前筛选与分页保持。取消不修改数据。修改日志只追加，保留操作人、时间、修改原因及前后记录；历史源表映射不改写。无编辑权限的角色隐藏编辑入口，同时在保存处理中校验权限。

新增验收：分别修改四类详情并重新打开核对；验证取消、未到诊与有效到诊冲突、缺少必填内容、越权保存及日志追加。测试覆盖四类保存及状态一致性，正式后端持久化仍待实现。

## 档案摘要直接编辑（2026-10-09）

四列详情弹窗打开即为可编辑表单。患者档案页的台账摘要直接提供编辑表单，可修改姓名、性别、年龄、电话、来源、原联系方式备注和心电图诊断结果，修改原因必填。点击“保存摘要”更新列表及档案并追加前后记录日志；保存资料后置为待医生复核，清除既有复核意见。风险、运营状态、到诊状态、责任医生与执行负责人作为摘要只读信息，相关业务修改沿用对应流程。

“重置”恢复本次表单加载时的值。医生查看只读摘要；服务端式保存处理也检查执行角色与对象可见范围。原型仍只保存页面内存。验收覆盖摘要保存、详情直接编辑、待复核状态、日志追加及医生只读。

最新交互：四列点击进入详情后直接修改；保存修改才写入，取消关闭不保存。三轮沟通额外保留下次计划说明，避免仅修改正文时丢失原有文字计划。医生仍为只读视图。
