# 1.4 院方全托管运营修正

## 依据与业务边界

《全托管：基于企业微信的患者流量运营服务介绍（西安图灵）》第 7、9、11、17 页把执行主体描述为专业运营团队：临床添加患者，团队服务患者并定期向医生汇报；出院小结是个体随访依据。AECG 医生工作站截图用于参考信息布局、筛选和报表展示，不等于要求院方医生或护士承担后台操作。

医院提供患者与诊疗数据、临床联系人及临床判断。我方项目经理和运营人员使用 HEALTH-ADMIN，安排随访、起草问询、记录实际院方审核、人工联系、异常升级、交付记录并复盘。医生/护士本期没有后台账号和工作队列。未来如院方需要专用审阅入口，应另行明确权限、身份认证、医院联调和验收标准。

## 可验收流程

1. 运营人员以医院 Mock 导入或人工补充患者，关联院方责任医生联系人与我方运营负责人；医生联系人没有账号。医生变更使尚未触达的旧审核失效。
2. 关联门诊或出院记录建立随访任务；运营人员核对 D3、D7、D30 等节点，按原报告起草并提交审核。正式 SOP 尚未交付，SOP 是团队使用系统完成业务的流程，不是发布在系统里的配置功能。
3. 院方医生在线下实际审核后，我方运营人员登记审核文本、时间、渠道和可追溯凭证。缺少凭证不能进入人工联系。登记本身不代表院方电子签名或系统已连通院方系统。
4. 运营人员人工联系，先核实身份；未接通留下原因、下次时间和计划。异常交由院方临床处置，运营人员记录处置依据，不由系统自动诊断或调药。
5. 服务完成后，运营人员将记录交付院方，并在获得实际反馈后登记时间、渠道和凭证。日报、周报和运营履约率按真实任务状态统计；报告发送是人工交付凭证，不是自动推送。
6. HEALTH-USER 只展示产品、分工及企业微信/小程序/Web 计划模式，不开放患者业务。

## 验收限制

演示数据全部为虚构，医院接口是 Mock；无院方统一身份、电子签名、消息通道或自动报告发送。运营登记的审核与反馈凭证可追溯，但真实性需线下核验。临床阈值、完整 SOP、筛查与精细化服务包仍需医院确认后另行设计。
