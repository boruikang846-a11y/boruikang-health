# 诊后主动干预开发顺序与患者上传说明 V1.3

2026-10-05。根据本次粘贴文本的业务目标继续开发，采用功能依赖及验收驱动顺序，不沿用其中按周、月安排的工期、预算或供应商架构承诺。保留现有Java/React工程，AI作为适配能力，不并行建立另一套患者主库。

## 本次完成的原型增量

患者中心顶部突出“上传患者信息”，支持Excel .xlsx与CSV，单文件5 MiB、最多500行。旧.xls、损坏/加密文件、缺少必填表头及错误行给出提示。必填为姓名、年龄、联系电话、科室、病种/管理原因；性别、来源编号、住院号等按模板填写。电话及编号按文本保留前导零。

操作：运营主管、护士或运营人员→患者中心→上传患者信息→下载模板/选择文件→核对错误和重复→指定责任医生、负责人、患者类型、来源场景→选择是否创建首次联系待办并填写截止时间→确认新增→查看批次及跳过原因→核验身份/服务授权/管家交接→建立门诊或出院服务旅程。

新增确认按钮展示预计新增人数，重复记录单列；按来源编号或证件号跳过已有记录，不凭共享电话合并，不覆盖既有分派。缺少去重标识时跨批次可能重复。任何错误行阻止整批，提供原行号问题清单。运营/护士只分配给自己，医生与平台管理员不能上传。

导入档案保持待核验、未服务授权、风险待评估。首次联系任务用于资料核验与服务说明，不等于医生批准的临床随访；任务时间由工作人员指定，不再用固定历史日期。管理原因仅为文件来源信息，不作为系统确诊。报告正文另行关联体检报告、门诊病历或出院小结。

导入成功页新增核验交接与旅程入口。所有档案、任务、导入结果仍只保存在当前页面，刷新恢复；文件在本地解析，不上传到服务器。本轮没有开发持久化数据库或真实文件上传API。

## 按依赖安排开发

| 顺序 | 工作包 | 可验收成果 |
|---|---|---|
| 1 | 患者底座与文件接入 | 身份、用途授权、服务团队、对象权限、批次导入、逐行错误、最终查重、事务与审计 |
| 2 | 报告与就诊事件 | 体检/门诊/出院分类、事件唯一键、原报告、版本、人工复核与来源证据 |
| 3 | 个体计划与任务闭环 | 病种及获批指南引用、时间/原用药/复诊复查/生活方式/危急指引字段、医生审核、任务实例化 |
| 4 | 人工执行与反馈 | 电话/获准企微渠道、问答、联系尝试、患者反馈、异常接单处理、复诊到院核验、就诊结果回流 |
| 5 | 全旅程与服务履约 | 门诊及住院出院旅程、排班交接、节点证据、服务包履约、退出与长期档案 |
| 6 | 真实接口与可靠性 | HIS、预约、企微身份/可用发送能力、小程序，回调鉴权、幂等、重试、对账和人工备用 |
| 7 | AI辅助与效果复盘 | 有引用的OCR/提取和草稿、医生审批、知识有效期、质控、反馈/到院口径，独立容量及恢复验证 |

测试和权限验证贯穿各包，不留到最后。体检、门诊、出院后的计划都必须绑定原始临床依据；用药字段先整理原医嘱及待确认项，不部署文本里的未验证自动用药推荐或风险阈值。未接通外部系统明确显示待接通。付费服务包先做服务履约台账，收费对接另行评审。

诊前危急/高危筛查继续保留医生复核、分级承接、邀约、到诊与结果。诊后主动干预承接报告归类、辅助管理计划、随访执行、在线问答、复查复诊、就诊结果和长期服务；患者全旅程入口按就诊事件串联两者。

## 文件导入后端开发契约

后续按现有POST、专用DTO、snake_case及Controller规范设计：模板下载、解析预览、批次校验、确认导入、批次结果/问题下载。确认包含request_id、批次/文件标识、人员分派、来源机构/系统、首次联系设置及校验版本。服务端最终查重、校验组织及操作范围，防止前端绕过。

单批创建档案及待办使用事务；重复确认返回同一结果；来源机构+系统+外部编号定位唯一映射。身份冲突进入人工核验，不静默覆盖。文档中的REST示例、FastAPI/Express及工期是参考内容，本次不据此迁移主业务技术栈。

## 验证与限制

实际读取合成XLSX与CSV，通过前导零、格式/大小、整批错误阻断、重复跳过、人员分派、首次联系日期、待核验授权及后续入口检查。现有旅程、诊后、筛查和权限回归通过。JavaScript语法与单文件打包检查通过。

没有浏览器点击和视觉验收，也没有真实企微、AI或医院接口联调。生产文件访问控制、并发查重、数据库事务、导入历史持久化及恢复仍属于后续开发。
