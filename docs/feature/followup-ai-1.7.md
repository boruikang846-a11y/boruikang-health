# HEALTH 1.7 按病历生成随访建议

版本：1.7，2026-10-01。随访模块用 DeepSeek 根据本任务关联的出院小结或病历正文起草随访建议。1.6 的医生审核、护士执行和人工联系全部保留。

## 业务路径

```
运营主管或平台管理员在接入设置填写 DeepSeek API Key 并启用
  → 运营人员或护士打开已关联报告的随访任务
  → 点击「根据病历生成随访建议」
  → 草稿写入任务，来源记为 AI
  → 提交责任医生审核；通过后才能人工联系
```

没有病历正文、未启用或调用失败时，不改已保存的草稿。基础问询起草仍然可用，且不调用外部接口。

## 发给模型的内容

只包含：记录类型、记录时间、病历正文（最长 8000 字）、原记录用药周期、原记录复诊日期、医生已写意见、可选的已发布宣教。不附带患者姓名、电话或其他档案字段。病历原文里的句子只当作资料，不当作给模型的指令。

AI 接入仅支持 DeepSeek 官方接口 `https://api.deepseek.com/chat/completions`，使用非思考模式。允许的模型是 `deepseek-flash` 和 `deepseek-v4-pro`。管理中心保留模型选择、API Key 输入和启用开关，不再提供接口选择或其他服务商选项。

运营主管从「运营设置 → 外部接入 → 配置 DeepSeek」进入；平台管理员从「接入设置 → 配置 DeepSeek」进入。保存已有 DeepSeek 配置时，API Key 留空保留原值。历史其他接口配置视为未配置；改配 DeepSeek 必须填写其 API Key，不沿用其他接口的密钥，也不在升级时自动启用。

## 验收

| 编号 | 结果 |
| --- | --- |
| A01 | 运营主管和平台管理员可保存接口、模型、API Key 和启用开关。密钥不在响应和日志中出现。运营人员、护士、医生不能保存 |
| A02 | 未启用、密钥为空、端点不是 DeepSeek 官方接口、模型不在允许列表时，生成失败且不写草稿；保存其他端点返回 400 |
| A03 | 任务没有关联病历，或病历正文为空时，提示无法生成，不发起外部调用 |
| A04 | 启用后，请求正文包含关联病历原文。返回内容写入草稿并标记 AI。超过 6000 字或空内容视为失败 |
| A05 | 失败、超时不覆盖已有草稿。审核、退回、人工联系规则与 1.6 相同 |
| A06 | 历史其他接口配置显示 DeepSeek 默认值与未配置状态；未填写新密钥不能启用。已有 DeepSeek 密钥可在留空保存时保留 |

接口见 [1.7 契约](../api/followup-ai-1.7.md)。原型见 [followup-ai-1.7.html](followup-ai-1.7.html)。
