# HEALTH-MVP-1 医患运营管理需求

版本：1.2，2026-09-28。最新范围调整：用户端只交付企业微信、小程序、Web 三种模式的公开介绍，患者业务需求待定。依据用户本轮会议纪要（会议日期 2026-08-28）、资料 PRD/研发规格、AECG 后台截图与运营 SOP。本轮明确的范围调整优先于既往会议和参考资料。

## 首版目标

完成医护后台闭环：医院接口导入（当前 Mock）/ 人工补充建档 → 绑定责任医生和运营人员 → 门诊/出院记录 → SOP 随访任务 → 建议草稿 → 医师审核 → 记录人工触达凭证 → 记录结果 → 异常人工升级 → 复诊到院证据与结果 → 周报。HEALTH-USER 仅公开介绍，不采集个人信息，不提供账号、填报、消息或入组业务。

医院年度托管是业务背景；参考中的商业估算不作为产品 KPI 或演示收入，不声称已验证，不实现医疗收入分成。首版不做处方、调药、诊断引擎、医保结算或自动患者回复。

## 角色与范围

- MANAGER：本院患者运营、分派、渠道、统计；代表运营团队制定、发布服务 SOP，并组织医生培训；维护其他知识草稿；不能批准临床建议。
- DOCTOR：只处理绑定自己的患者；审核建议、风险分层、异常处置；接受运营团队的 SOP 培训并按流程协作，审核宣教与服务包内容，不制定或发布服务 SOP。
- NURSE / OPERATOR：只处理分配自己的患者；建档、记录、随访、记录已审核建议的人工触达、预约协同；不能代替医生批准。
- PLATFORM_ADMIN：只维护接入配置，不默认访问患者。
- 患者访问者：公开阅读产品介绍、企业微信/小程序/Web 规划、服务流程与上线阶段。无需登录，无业务 API。

MVP 单院试点，但所有业务数据带 hospital_id，服务端从账号取医院和角色；客户端不得自述角色/医院。患者及病历以医院接口导入为主，人工补充为辅；当前使用虚构医院 Mock，不提供患者自助认领。

## 状态与关键字段

patient：name, gender, age, phone, department, disease, risk_level（UNKNOWN/LOW/MEDIUM/HIGH/CRITICAL）, lifecycle（ENROLLED/MANAGING/PAUSED/CLOSED）, doctor_id, owner_id, channel_id, service_package_id。

care_task.task_type：FOLLOWUP/CONSULTATION/ALERT/REVISIT。

FOLLOWUP/CONSULTATION：PENDING → IN_PROGRESS → PENDING_REVIEW → APPROVED → CONTACTED → COMPLETED；审核可 REJECTED，再起草；未触达可 CANCELLED。只有 DOCTOR 可批准，人工触达记录必须基于 approved_text，并填写 evidence（联系时间、方式和核验结果）；触达记录与沟通留痕/审计同事务，重复记录拒绝；不等同于系统发送。

ALERT：PENDING → IN_PROGRESS → ESCALATED → COMPLETED。P0/P1 必须升级后由绑定医生填写结果闭环。不自动解释临床数值；由医护人工创建待处理事件，不代表诊断。

REVISIT：PENDING → BOOKED → ARRIVED → COMPLETED；BOOKED 可 NO_SHOW；非终态可 CANCELLED。到院 evidence 必填，完成 outcome 必填。

所有任务变更带 version 并用条件更新防重复领取、过期审核、重复触达记录。所有临床状态变化写审计。优先级 P0/P1/P2/P3；逾期按 due_at 与数据库当前状态计算，不通过覆盖业务状态丢失审核进度。

负责人变更同时更新全部任务的当前归属与版本；旧页面上的审核/触达请求必须返回冲突。更换责任医生后，未触达建议须由新医生重新审核。已触达/已结束任务的审核人、正文和审计保留执行时的记录，查询权限随当前患者归属变更。公开介绍页没有患者档案接口。

## AI 与 SOP 边界

已找到运营 SOP：首次身份核对、联系记录、异常升级、次日复诊核对、日报归档、周复盘。参考模板尚不是某试点医院签字批准的临床 SOP；演示模板只问询与收集，不配置诊疗阈值。服务 SOP 由我们运营团队制定并培训医生；医生负责医学判断与个案建议审核。涉及诊疗的依据以原报告、原医嘱和责任医生核对为准。

模板草稿必须明确标识 TEMPLATE；AI 草稿标识 AI，保留来源知识/原记录编号，经医生修改审核后才可人工触达。AI 未配置或失败时给出明确失败，不假装模型输出、不自动回退冒充 AI。无外部凭证时模板路径仍完整可用。AI 仅辅助生成问询建议，不诊断、不推算药物疗程、不独立改变治疗计划。

审核抽屉必须展示当前任务直接关联的原病历和原始咨询，不能用患者最新一条记录替代；详情读取仍按患者归属校验。

## 本期外部依赖与后续

医院负责提供接口、授权和映射。公众号/企微需 AppID、企业主体与开放平台关联方案；UnionID 并非所有用户都有，也不是医院患者号。HIS 患者号和就诊事件为复诊确认来源，无法接入时使用人工核验并记录证据。首版不声称微信自动发信、短信登录、OAuth、真实 HIS 同步或自动周报投递已可用；这些渠道待医院与平台凭据交付后单独联调。管理端账号密码与人工触达记录为 MVP 可用路径。

所有任务写入在短事务内先以 PatientExample 锁定患者行，再条件更新任务，防止分派与创建/触达记录同时发生时越权或漏同步。锁查询按唯一患者主键定位，不使用分页；列表仍使用 PageHelper。

本轮新增需求优先于此前会议纪要中关于患者端首版交互的范围。医护后台可为电话或当面问询人工创建 CONSULTATION/ALERT，并以原始记录作为依据。企业微信、小程序、患者 Web 功能与身份关联均为后续规划。

## 1.2 系统图解与出院随访依据

- H13：两端以 HTML/CSS 展示系统全貌、角色分工、随访依据和服务流程。管理端 `/overview` 从登录页与侧栏可达；患者端直接呈现整体介绍，无新患者业务入口。标清后台 MVP、当前介绍页与规划渠道，图中的连接不表示接口已接通。
- 服务 SOP 回答“团队按什么流程做”；出院报告回答“这位患者需要跟进什么”。出院报告是很多随访的重要依据，也支持门诊和体检记录，不能把全部患者套入同一套内容。
- 本期先从医院 Mock 导入或由团队人工补充，再核对报告摘要（出院诊断、原医嘱、注意事项、随访重点等原文事实）、原报告用药周期与复诊日期；不新增上传、OCR、自动读取或临床计划推断。
- 保存出院报告后建立关联任务，任务始终显示该份报告，不替换成最新记录。默认次日任务是团队的“核对报告并准备随访”待办，不代表报告建议的临床随访时间。
- 模板生成基础问询，并加入关联记录已有的用药周期核对和复诊日期问询；报告自由文本由团队对照侧栏补充个体随访内容，再交责任医生审核。AI 仍不上传报告全文。缺失字段不得猜测，无报告不阻断非出院场景的任务。
- SOP 新建、修改、发布仅 MANAGER 可执行；DOCTOR 只读/使用 SOP，可维护并审核其他知识。知识类型建立后不可变，避免把 SOP 改类型绕过权限。SOP 培训本期仅说明职责，不新增培训管理模块。

## 医院接口 Mock（本期新增）

H14：医院数据是主要来源。当前未对接真实医院，提供内置医院接口模拟适配器和受鉴权 HTTP 预览端点，返回虚构患者、门诊记录、出院报告；后续替换适配器接真实接口。管理端“医院数据”支持查看模拟响应、选择责任医生/运营人员、同步、查看导入结果。仅 MANAGER 操作。不得显示真实医院已接通。

模拟场景 NORMAL（2 位虚构患者、3 份报告）、EMPTY（空数据）、UNAVAILABLE（503 接口不可用）。同步先取完整模拟响应，成功后在一个数据库事务内按 hospital_id + source_system + hospital_patient_id 建档，按 hospital_id + source_system + external_id 去重病历；新增报告沿用关联随访/复诊任务流程。重复同步不重复建档或任务，不覆盖已审核记录或已分派负责人。同手机号不做自动合并。模拟患者和报告全程标记 HOSPITAL_MOCK。接口失败不产生部分业务数据，页面显示实际失败。

MOCK 在 local/test/dev 开启，prod 禁用；无自动定时导入。后续真实医院的增量游标、报告修订/撤回、身份合并和授权需依据医院契约另行联调。
