1.9 企业微信与公众号患者沟通

工作人员点发送，系统才调用微信接口，
结果如实保存

1.9 把医院企业微信和公众号接进现有系统：工作人员点击发送时调用微信官方接口，保存接口返回的真实结果。临床建议仍须责任医生本人在系统里审核通过后才能发送；短信和没有接入的渠道继续用 1.5 的“人工已发”登记。

  1. 填写凭证

    企业微信、公众号各一张卡片；密钥只写不读，不回显。

    运营主管 / 平台管理员

  2. 测试连接

    真实取一次凭证：成功显示“已接通”，失败显示微信返回的错误码；只保存未测试是“已配置 · 未验证”。

    运营主管 / 平台管理员

  3. 配置回调

    把回调地址配到微信后台。签名不对返回 403、不落数据；重复推送只记一次。

    微信 → 系统

  4. 活码与成员账号

    给渠道生成企微活码和公众号带参二维码，给工作账号登记企业微信成员账号。

    运营主管

  5. 患者扫码

    患者扫码加企业微信好友或关注公众号，微信把事件推到回调地址。

    患者 / 微信

  6. 联系人待绑定

    系统生成“微信联系人”，带上来源渠道和添加成员，还没有对应到患者档案。

    系统

  7. 核实并绑定

    核实身份后人工绑定患者档案；不按手机号、昵称、UnionID 自动合并。解绑要写原因。

    运营人员 / 护士 / 主管

  8. 发送三类消息

    文字（公众号要求 48 小时内有互动；企业微信建群发任务，成员确认后发出）、公众号模板消息、医生已审核的正文（取自任务，页面不能改）。

    运营人员 / 护士 / 主管

  9. 患者回复

    公众号文字来信入库，标为“待处理”，列表显示未处理条数。

    患者 / 微信

  10. 处理或转咨询

    回复、标记已处理；已绑定患者的来信可转成咨询任务，沿用起草、责任医生审核、联系流程。

    运营人员 / 护士 / 主管

  11. 时间轴与留痕

    微信收发并入患者时间轴和档案“微信沟通”页签；发送、绑定、配置变更都写操作留痕。

    系统

角色分工

角色在 1.9 里做什么
运营主管配置接入、测试连接、同步联系人、生成活码、登记成员账号；查看和处理全院联系人与消息
运营人员、护士查看待绑定联系人和自己负责患者的联系人；绑定、发送、处理消息
责任医生审核随访与咨询正文；在自己负责的患者档案里只读查看微信沟通记录，不能发送
平台管理员只配置接入与测试连接，不能看联系人和消息

不做与边界

  • 不做会话存档、企微客户群、朋友圈、企业标签同步、按标签群发、定时推送、自动回复、AI 对话、网页授权、小程序、菜单管理、图片与文件收发。
  • 未开通会话存档，系统读不到企业微信里的聊天内容，只同步好友关系和添加、删除事件。
  • 不向未绑定的联系人发送已审核正文。
  • 发送成功只表示微信接口受理，不代表患者已读，不能代替联系结果登记。
  • 企业认证、可信 IP、模板申请、客户联系权限由医院在微信后台完成，系统只如实显示接口返回。
  • 模拟通道只用于 local、test、dev 演示，全程标注，不代表已接通。演示数据全部虚构。

消息状态：发送中 → 已发出 / 待成员确认 / 失败（保存微信错误码）；来信：待处理 → 已处理。删除好友或取消关注后联系人标为“已失联”，记录保留。
