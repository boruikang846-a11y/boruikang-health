# HEALTH 1.6 院方医生、护士登录协作

版本：1.6，2026-09-30。用户 2026-09-30 拍板：**医生负责查看报告和审核随访意见，医生和护士都需要登录**。本版把 1.4 起"院方医生、护士不登录，由运营人员登记院方审核与反馈凭证"的做法改回院方本人在系统里操作。1.5 的台账、指标与随访执行全部保留。

这一拍板同时回答了 2026-09-29 需求差距报告待拍板项里的"医生端"部分：医生端是管理端里按角色开放的工作台，不另做 App；患者端仍只有介绍页。

## 角色与分工

| 角色 | 谁 | 登录后负责 | 能看到的患者 |
| --- | --- | --- | --- |
| MANAGER 运营主管 | 我方 | 全院运营、分派责任医生与负责人、医护账号、医院数据同步、配置 | 全院 |
| OPERATOR 运营人员 | 我方 | 随访执行：起草随访意见、提交医生审核、联系患者、登记结果、邀约预约、复诊核实、异常响应与升级 | 分配给自己的 |
| NURSE 护士 | 院方 | 与运营人员相同的随访执行，处理分配给自己的患者 | 分配给自己的 |
| DOCTOR 责任医生 | 院方 | **查看报告**（确认已阅、写医生意见）、**审核随访意见**（通过或退回）、查收随访结果并反馈、处置升级的异常、审核发布宣教内容 | 自己负责的 |
| PLATFORM_ADMIN | 平台 | 接入设置，不接触患者 | 无 |

患者的"负责人"可以是运营人员、护士或运营主管；"责任医生"必须是本院启用中的医生账号。医生对自己负责的患者只读档案，不做运营登记。

## 业务路径（本版变化的部分）

```
医院同步 / 人工录入出院、门诊、体检报告
  → 责任医生"待阅报告"：查看原文，确认已阅，可写医生意见（意见显示给起草随访的人）
  → 运营人员或护士按报告起草随访意见 → 提交医生审核
  → 责任医生在系统里审核：通过（可改写最终正文）或退回（写原因）；审核同时把关联报告记为已阅
  → 运营人员或护士按通过的正文人工联系患者、登记反馈、完成
  → 责任医生"待查收结果"：查看随访记录与患者反馈，查收并写反馈
异常：运营人员或护士响应 → 升级 → 责任医生记录处置去向与结果后关闭；失联类异常由运营确认后直接关闭，不进医生队列
宣教：运营主管起草 → 医生审核发布
```

## 功能与验收

| 编号 | 功能 | 可验证结果 |
| --- | --- | --- |
| C01 | 医护账号 | 运营主管在"医护账号"新增医生、护士、运营人员账号（账号、姓名、角色、科室、初始密码 8–64 位）；可停用 / 启用、重置密码；停用或重置后该账号的登录立即失效；不能停用自己，不能改运营主管和平台账号 |
| C02 | 修改密码 | 任何登录用户可凭原密码改新密码；改后旧登录失效，当前窗口换发新登录继续使用 |
| C03 | 按角色进入 | 登录页不再写"院方医生和护士无需登录"；医生登录进入医生工作台，只看到医生菜单；护士与运营人员进入工作台，菜单相同 |
| C04 | 医生工作台 | 显示我的患者数、高风险数，以及四个待办数：待审核随访意见、待阅报告、待查收随访结果、待处置异常；每项可点进对应清单 |
| C05 | 审核随访意见 | 医生只看到自己负责患者的待审核意见；详情同时展示患者、关联报告原文与已有医生意见、草稿正文与来源；通过时正文必填且可修改，退回时原因必填；审核人与时间由系统记录；运营人员、护士、运营主管调用审核一律拒绝 |
| C06 | 查看报告 | 医生按"未阅 / 已阅 / 全部"和报告类型查看自己患者的出院、门诊、体检报告（体征记录不计入）；确认已阅时可写医生意见，已阅后可更新意见；运营人员和护士在任务与患者档案里看到"医生已阅 · 意见" |
| C07 | 查收随访结果 | 完成的随访进入责任医生"待查收"；医生查看已审核正文、联系记录、患者反馈与问题后填写反馈并查收；运营侧不再登记查收凭证 |
| C08 | 处置异常 | 升级后的异常进入责任医生"待处置"；医生选择处置去向并写结果后关闭；运营人员和护士不能关闭临床异常；失联类异常由运营人员或护士写明核实情况后直接关闭 |
| C09 | 宣教审核 | 运营主管保存草稿；医生查看内容后审核发布，发布人与时间由系统记录；运营主管不再登记院方审核凭证 |
| C10 | 护士工作 | 护士登录后与运营人员同一套随访、邀约、预约、复诊、异常响应页面，只处理分配给自己的患者；不能审核、不能关闭临床异常、不能改配置 |
| C11 | 分派 | 新建 / 编辑患者、医院数据同步、渠道、活动、任务转交的负责人可选运营人员、护士或运营主管；责任医生只能选启用中的医生账号；更换责任医生后，尚未联系患者的审核作废，需重新提交新医生审核（沿用） |
| C12 | 医生只读 | 医生打开患者档案只读，不出现建档、录入、邀约、预约、签约、转诊、联系等按钮；对应写接口返回无权限 |

## 数据口径

- `health_account` 增加 `department`（科室）；角色码 `DOCTOR`、`NURSE` 恢复。
- 删除 `hospital_clinician` 表：责任医生、转介医生、预约医生、转诊反馈医生、宣教审核人都指向 `health_account` 中的医生账号。
- `care_record` 增加 `doctor_viewed_at`、`doctor_viewer_id`、`doctor_opinion`（医生已阅与意见）。
- `care_task` 删除 `review_channel`、`review_evidence`、`handover_channel`、`handover_evidence`；审核人、审核时间、查收时间、医生反馈沿用原列，由系统按登录医生写入。
- `knowledge_entry` 删除 `review_channel`、`review_evidence`；发布人与时间由系统写入。
- 发版按全量口径：备份后清库，DDL → DML → dev/DML 重建。

## 不在本版

医生排班、会诊、电子签名 / CA、按科室自动分派、医生移动端、给医生发短信或企微提醒、医生端统计报表。医生看到的是自己负责患者的待办；是否要科室级视图（科主任看全科）待用户再定。

开发期账号口令按骨架规范明文存储，只能用于虚构数据环境；真实医院医护账号上线前必须先定口令存储与账号开通流程（见 [安全边界](../security/health-mvp.md)）。
