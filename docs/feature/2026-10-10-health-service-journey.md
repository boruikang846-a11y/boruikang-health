# 诊后健康服务中心可执行旅程 Implementation Plan

**Goal:** 在指定静态原型中将三个中心改为患者全旅程办理工作台，明确运营、护士、医生职责，支持每步编辑与结果留痕。

**Architecture:** 复用患者主档和 afterCareCases，计划、报告、随访、问题和日志沿用原个案对象。新增 serviceJourney 仅为 2.4 原型的阶段节点和协作分工扩展，咨询与转诊保留现有工作单。正式 API 仍为 2.3，本轮不把静态节点能力声明成已落库能力。

**Tech Stack:** 原生 JavaScript / HTML / CSS，Node VM 原型回归测试。

## 取舍与责任

采用参考材料中的来源关联、患者连续档案、人工审核、结构化执行反馈和真实复诊证据。暂不采纳自动诊断、处方推荐、原始影像分析、自动发送、在线训练或新增独立微服务。SOP 体现为业务办理，不建设规则发布引擎。

采用同一患者个案的连续办理工作区，比孤立工作单更便于交接，比重建诊疗系统更符合本仓职责。三个中心分别保留专属字段，院前 / 院中 / 院后贯通。已完成步骤修改需理由，医学依据和计划变更使后续审核失效，历史记录保留。

- 运营：全旅程接入与授权、资料收集、预约 / 入院协调、到院核验、服务交接、随访执行、记录、复诊核验与闭环。
- 护士：医疗护理核对、执行准备质控、随访质量复核，可退回运营整改；不负责运营服务执行。
- 责任医生：查看原报告、确认医学依据、编辑审核个案计划、查收本轮反馈、处置临床问题、确认复诊医学安排。

## 实施与验证

1. 新建 `web/health-service-journey.js` 与 CSS；以既有个案作为唯一记录，增加三中心具体节点、三角色协作人员、完成条件与字段。新增版本校验、草稿与完成分离、未接通重试、审核退回、修订失效及可追踪问题闭环。
2. `interactive.html`、`build-preview.py` 和测试 harness 加载新模块；保留旧个案与台账链接，名称替换覆盖菜单和正式 React 文案，不改无关筛查功能。
3. 新建 `tests/health-service-journey.test.cjs`：三条路径、角色边界、医生审核、计划修订、复诊事实、未接通、授权失效、跨患者报告、关闭阻断和旧版本写入。
4. 更新设计和功能说明，明确静态原型与 2.3 正式接口的差距；运行原型全量回归和 React 构建。
5. 指定目录更新前备份，逐文件同步并保留该目录已有差异；生成新名称的离线入口。浏览器核验实际点击、角色切换、编辑保存和手机宽度布局。
6. 提交工作分支，更新已授权的草稿 PR 28，不合并、不部署。

## 追加要求：AI 智能体规划

已纳入用户追加要求。增加结构化规划输入（报告、目标、基线、困难、周期、宣教、缺项），生成三阶段可编辑任务、规划来源与版本记录，仍需当前责任医生编辑审核。当前仅模板模拟；不新增真实模型配置或调用。

最新责任分工已按用户补充修正：全旅程服务属于运营；医护负责医疗与质控。三条路径各 15 步，新增两处护士质控及独立医护待办入口。
