1.5 运营台账闭环

从检出到入组，
每一步都有台账、SLA 和指标

1.4 只有随访任务和交接记录。1.5 把院方运营团队真实在做的事装进系统：患者池、邀约、预约到诊、服务包签约、随访方案展开、转诊、短信话术登记，以及由这些台账直接算出来的十项指标。临床判断仍在院方医生；系统不诊断、不调药、不发消息、不收款。

1

检出入池

心电网络 / 体检 / 筛查 / 门诊 / 住院；粘贴导入或人工录入；来源编号去重
2

判定高危

记录院方判定结论与依据；非高危写原因；作废写原因
3

建档入组

进入患者中心；按风险 SLA 开出首次联系任务（重点 2h / 高 24h / 中 72h / 低 7d）
4

多轮邀约

11 种结果；接通即关首触；连续未联系上 N 次自动升级失联异常
5

预约到诊

预约 → 提醒 → 到院 / 爽约 / 取消 → 结果；镜像复诊任务；有效到诊标记
6

签约管理

服务包 SKU 记录价格与单号；激活按方案生成任务；到期 / 结案 / 升级

运营团队在系统里做什么

  • 维护机构网络、活动、SLA、短信与话术模板
  • 把筛查名单粘进患者池，判定后建档
  • 逐轮记录邀约结果、下次时间与凭证
  • 登记预约、提醒、到院与结果
  • 签约服务包、激活方案、处理到期与升级
  • 发起与跟踪转诊，登记院方反馈
  • 登记已发短信、用药、代录指标
  • 看队列、看指标、看按人绩效，向院方交周报

系统不做什么

  • 不做医学判断：风险、处置去向都是登记院方结论
  • 不发短信、不外呼、不推微信：只登记已发凭证
  • 不收款：服务包价格与订单号只做记录
  • 不自动改患者阶段到 LOST/CLOSED：需人工确认并填原因
  • 不接真实医院接口：来源 ID 与幂等保留，Mock 先行
十项指标口径、SLA 默认值、随访方案节点都可按医院配置；演示种子全部虚构。

患者阶段与任务类型

患者阶段由什么推动
ENROLLED 已入组建档（患者池入组或人工新建）
CONTACTED 已触达接通类邀约结果
BOOKED 已预约登记预约
ARRIVED 已到院核实到院 / 转诊到达
MANAGING 管理中服务实例激活
REVISIT_DUE 待复诊服务期满标记到期
PAUSED / TRANSFERRED / LOST / CLOSED人工在档案里设置并填写原因；去世由邀约结果推动结案
