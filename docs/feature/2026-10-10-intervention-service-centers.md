# 诊后主动干预中心实施方案

**Goal:** 将诊后主动干预升级为门诊、住院、体检、咨询、转诊五个可执行服务中心，按院前、院中、院后管理工作单。

**Architecture:** 五个中心共用患者权限、工作单、修改留痕与医生审核；保留原患者档案、个案计划、房颤管理及旧链接。正式 React 通过新增 Java/MyBatis 接口持久化；离线原型使用同一字段与状态规则的虚构演示数据。

**Tech Stack:** React 18 / Ant Design 5、Spring Boot / Java 21、MyBatis、MySQL 与 H2、离线 HTML 原型。

## 设计裁决与参考提取

用户本次要求优先：五个子目录必须都是工作入口，院前、院中、院后是可编辑工作单的阶段，不是流程说明。侧栏改名，默认进入门诊工作台；中心内提供工作队列、患者详情、办理表单、审核反馈、操作记录。

附件第一张图提取：待响应及超时队列、咨询动态、随访动态、就诊转化、评价投诉、渠道统计。数字由系统记录计算；不复制图中患者、机构、业绩数字。
PDF 第 4、7、12、15–19、25 页提取：一站式服务、院内指引、知识条目、门诊/出院/体检报告关联、随访与实际到院追踪。商业指标和响应承诺不作为系统默认保障；知识内容和医学建议需院方提供与审核。

## 功能分布

| 中心 | 院前 | 院中 | 院后 |
| --- | --- | --- | --- |
| 门诊 | 导诊咨询、预约准备 | 到院核验、检查指引 | 门诊随访、复诊跟踪 |
| 住院 | 入院协调、资料准备 | 住院服务、出院交接 | 出院随访、康复反馈 |
| 体检 | 套餐咨询、检前准备 | 检查协调、漏项跟进 | 报告解读审核、异常复查 |
| 咨询 | 就医咨询、报告咨询 | 院内咨询、投诉协办 | 随访咨询、评价回访 |
| 转诊 | 转诊申请、接收协调 | 到院核验、诊疗反馈 | 回转交接、转诊随访 |

## 任务 1：持久化工作单

新增 common/intervention 的 DTO、service、model/mapper 及 admin/intervention/controller；SQL 完整 DDL、local DDL、增量迁移同步。查询限定当前医院及当前患者分派范围。患者责任团队继承主档，改派沿用现有患者分派。
新增/编辑携带版本、变更原因；工作单临床内容必须关联同一患者原报告，修改后审核失效。医生本人审核、退回；运营/护士登记办理结果；完成后再核验闭环。只追加工作日志，不修改旧日志。

## 任务 2：正式管理端

新增 InterventionCenter.jsx 与专用样式，App.jsx 增加五个子菜单。中心/阶段筛选、搜索、状态队列、统计、工作单编辑、结果办理、医生审核、到院证据、评价、历史记录。保留旧 step 链接进入 CareWorkspace。

## 任务 3：交互原型

新增 intervention-center.js/css；接入 interactive.html 与打包器。五中心独立样例、队列筛选、新建编辑、办理记录、临床审核失效及权限检查、咨询响应和动态看板。保留现有筛查及企微连续服务扩展。所有演示数据虚构，不发送外部消息。
