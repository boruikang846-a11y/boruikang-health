# HEALTH 1.9 企业微信与公众号患者沟通

版本：1.9，2026-10-04。用户要求：运营团队实际通过医院企业微信和微信公众号与患者沟通、管理患者，把这部分接进现有系统。依据《全托管：基于企业微信的患者流量运营服务介绍》《基于企业微信的患者运营及全病程管理》的做法（加好友、渠道活码、好友与患者档案匹配、按随访节点触达、公众号提醒），只取与现有台账衔接的最小闭环。1.2–1.8 的建档、审核、人工联系、台账与导入全部保留，本版只做增量。

2026-10-04 修订（用户要求）：企业微信和公众号是两个独立模块。管理端左侧菜单拆成「企业微信」`/wecom` 与「公众号」`/official-account` 两项，各自只显示本通道的接入状态、联系人、同步与模拟入口；患者档案的页签也拆成「企业微信」「公众号」两个。接口、数据和权限不变。

本版起，管理端不再只是"登记已发"：工作人员点击发送时，系统调用微信官方接口发出消息，并保存接口返回的真实结果。1.5 的"人工已发"登记继续保留，用于短信和没有接入的渠道。

## 拍板项的默认口径（用户未另行拍板前按此执行）

| 拍板项 | 本版口径 |
| --- | --- |
| 系统是否代发消息 | 是。只在工作人员点击发送时调用接口；不做定时发送、自动回复和按标签群发 |
| 临床内容 | 随访意见仍须责任医生本人审核通过。微信发送"已审核正文"时由服务端取任务里的审核正文，不接受页面传入 |
| 患者身份 | 微信好友或粉丝与患者档案是两套身份。工作人员核实后人工绑定；不按手机号、昵称、UnionID 自动合并 |
| 企业微信聊天正文 | 未开通会话存档，系统读不到成员与客户的聊天内容。只同步好友关系和添加、删除事件；发消息走"群发任务"，成员在企业微信里确认后才发出 |
| 公众号凭证 | 使用 stable_token 接口取凭证，避免把医院现有公众号后台的 access_token 挤掉 |
| 患者端 | 仍是公开介绍页，新增一段虚构的微信互动演示。不做网页授权、患者自助绑定和小程序 |
| 模拟通道 | local、test、dev 可把通道设为"模拟通道"用于演示，页面全程标注；prod 不允许。模拟通道不代表已接通 |
| 凭证存储 | 沿用开发期口径明文存库，只写不读回显。真实医院上线前随口令方案一并处理 |

## 业务路径

```
运营主管或平台管理员填写企业微信 / 公众号凭证 → 测试连接（真实取凭证）→ 把回调地址配到微信后台
  → 运营主管给渠道生成企微活码 / 公众号带参二维码，给工作人员登记企业微信成员账号
  → 患者扫码加好友或关注 → 微信回调 → 系统生成"微信联系人"（待绑定），带上来源渠道
  → 工作人员核实身份，把联系人绑定到患者档案
  → 发消息：文字、模板消息、医生已审核的随访正文 → 保存真实发送结果
  → 公众号患者回复 → 进入待处理 → 回复、标记已处理，或转成咨询任务交责任医生审核
  → 全部进入患者时间轴与操作留痕
```

## 角色

- MANAGER：配置接入、测试连接、同步联系人、生成活码、登记成员账号；查看和处理全院联系人与消息。
- OPERATOR、NURSE：查看待绑定联系人和自己负责患者的联系人；绑定、发送、处理消息。
- DOCTOR：在自己负责的患者档案里只读查看企业微信、公众号沟通记录；不能发送。
- PLATFORM_ADMIN：只配置接入与测试连接；不能看联系人和消息。

## 功能与验收

| 编号 | 功能 | 可验证结果 |
| --- | --- | --- |
| W01 | 接入配置 | 企业微信：企业 ID、客户联系 Secret、回调 Token、EncodingAESKey。公众号：AppID、AppSecret、回调 Token、EncodingAESKey（明文模式可不填）。密钥不回显、不进日志；留空保留原值。运营人员、护士、医生不能保存 |
| W02 | 测试连接 | 用已保存凭证实际取一次 access_token。成功显示"已接通"和时间；失败显示微信返回的错误码与原因。只保存未测试时显示"已配置 · 未验证"。修改企业 ID / AppID、Secret 或通道类型后回到未验证；只改回调 Token、AESKey 不影响。模拟通道不能测试连接 |
| W03 | 回调接收 | 两个公开回调地址，按医院区分。校验签名，支持加密消息；签名不对返回 403，不落任何数据。同一事件重复推送只记一次 |
| W04 | 微信联系人 | 加好友、关注、扫码事件生成联系人：渠道、外部 ID、昵称（公众号拿不到昵称）、添加成员、来源渠道、关系状态。删除好友、取消关注后标为"已失联"，不删记录 |
| W05 | 同步联系人 | 运营主管手动同步：企业微信按已登记成员账号拉客户列表，公众号拉关注者列表。只新增和更新，不解绑；单次上限 1000 条，超出时提示 |
| W06 | 绑定患者 | 工作人员从自己可见的患者里选择并绑定；一个联系人只能绑一位患者，一位患者可以有多个联系人。解绑要写原因。绑定、解绑写入患者留痕 |
| W07 | 发送文字 | 公众号走客服消息，要求患者 48 小时内有过互动，否则提示改发模板消息。企业微信创建群发任务，状态为"待成员确认"，可刷新查看是否已发出 |
| W08 | 发送模板消息 | 公众号模板消息：模板库里登记微信模板 ID 和字段，发送前可改字段内容。返回的消息 ID 入库；微信回调送达失败时改为失败并记录原因 |
| W09 | 发送已审核正文 | 只在任务"已审核"、审核人是患者当前责任医生时可发；正文取自任务，页面不能改。按文字通道发出，同样受公众号 48 小时和单条长度限制。发送不改变任务状态，联系结果仍按 1.3 登记，联系方式新增"微信" |
| W10 | 发送结果如实 | 状态：发送中、已发出、待成员确认、失败。失败保存微信错误码。同一次点击重复提交只发一次。联系人已失联、通道未启用时不调用接口。调用中途进程中断的记录停在"发送中"，系统不重发；工作人员向患者核实后重新点击发送 |
| W11 | 患者回复 | 公众号文字消息入库并标为待处理，列表显示未处理条数。图片、语音等只记一条类型说明（如「[图片]」），同样计入待处理。任一条消息发送成功或点"标记已处理"后清零；转咨询任务只把那一条标为已处理 |
| W12 | 转咨询任务 | 已绑定患者的来信可转成咨询任务，原文作为患者原始咨询；后续起草、医生审核、联系沿用现有流程。同一条来信只转一次 |
| W13 | 渠道活码 | 渠道管理里生成企业微信"联系我"二维码和公众号带参二维码，参数为渠道编号。患者扫码后联系人自动带上来源渠道 |
| W14 | 欢迎语 | 模板库有启用的欢迎语（渠道选"微信"、场景选"欢迎语"，企业微信与公众号共用）时，加好友或关注后发送一次，并记入会话；没有模板或模板里还有 {占位} 则不发。公众号欢迎语走客服消息 |
| W15 | 成员账号 | 运营主管给工作账号登记企业微信成员账号；回调与同步据此显示"添加成员"是系统里的谁 |
| W16 | 档案与留痕 | 患者档案新增"企业微信""公众号"两个页签，各显示本通道已绑定的联系人；时间轴合并微信收发；所有发送、绑定、配置变更写操作留痕 |
| W17 | 模拟通道 | 通道设为模拟时，发送、同步、活码都返回模拟结果，记录标"模拟"；运营主管可模拟一次关注或来信。prod 保存模拟通道被拒绝 |
| W18 | 介绍页互动演示 | HEALTH-USER 介绍页新增"微信互动"：企业微信、公众号各一套虚构对话，左侧是患者手机上看到的，右侧是系统里同时发生的事；可播放、逐步查看，支持手机与中英文。不连接微信、不请求后端、不采集信息 |

## 状态与枚举

- 通道 `channel`：WE_COM 企业微信、WECHAT_OFFICIAL 公众号。
- 接入状态 `status`：NOT_CONFIGURED 未配置 → CONFIGURED_UNVERIFIED 已配置未验证 → CONNECTED 已接通 / FAILED 连接失败；模拟通道显示 MOCK。
- 联系人关系 `relation`：ACTIVE 有效、REMOVED 已失联（删除好友或取消关注）。绑定状态由 `patient_id` 是否为 0 表示。
- 消息方向 `direction`：INBOUND 患者发来、OUTBOUND 我方发出。
- 消息类型 `kind`：TEXT 文字、TEMPLATE 模板消息、APPROVED_ADVICE 已审核正文、WELCOME 欢迎语、EVENT 关系事件（关注、取消关注、加好友、删好友）。
- 消息状态 `status`：出站 SENDING 发送中 → SENT 已发出 / PENDING_CONFIRM 待成员确认 / FAILED 失败；入站 RECEIVED 待处理 → HANDLED 已处理。
- 模板 `channel` 新增 MP_TEMPLATE（公众号模板消息，需登记微信模板 ID）；`scene` 新增 WELCOME。
- 联系记录 `method` 新增 WECHAT。

## 数据模型（新增/变更）

- `integration_config` 新增：app_id、callback_token、aes_key、mode（LIVE/MOCK）、verified_at、last_error。
- `health_account` 新增 wecom_user_id；`intake_channel` 新增 wecom_config_id、wecom_qr_url、official_qr_url；`message_template` 新增 external_template_id。
- 新表 `wechat_contact`（微信联系人）、`wechat_message`（微信收发记录，按 `(hospital_id, request_key)` 幂等）。

## 页面路径

管理端新增两个独立菜单：`/wecom` 企业微信、`/official-account` 公众号，各自是本通道的联系人列表、待绑定、会话抽屉与发送；待处理来信只出现在公众号（企业微信没有会话存档）。`/settings` 外部接入里企业微信、公众号两张卡片可配置和测试；`/channels` 增加活码；`/accounts` 增加企业微信成员账号；`/patients/:id` 增加"企业微信""公众号"两个页签；任务抽屉增加"微信发送已审核正文"；短信与话术模板支持公众号模板消息和欢迎语。用户端介绍页新增 `#wechat` 微信互动演示。原型见 ../demo-static/web/admin/wechat-channels-1.9.html，接口见 [1.9 契约](../api/wechat-channels-1.9.md)。

## 不做与边界

不做会话存档、企微客户群、朋友圈、企业标签同步、按标签群发、定时推送、自动回复、AI 对话、网页授权、小程序、菜单管理、图片与文件收发。不向未绑定的联系人发送已审核正文。发送成功只表示微信接口受理，不代表患者已读；不能代替联系结果登记。微信侧的企业认证、可信 IP、模板申请、客户联系权限由医院在微信后台完成，系统只如实显示接口返回。演示数据全部虚构。
