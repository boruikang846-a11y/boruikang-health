# HEALTH-MVP 1.3 随访执行与护士统计

2026-09-28。用户要求发布前继续迭代，患者端仍仅介绍产品。SOP 是团队使用系统完成业务的流程，不是系统功能；正式 SOP 尚未取得。此需求取代 1.2 中“制定、发布 SOP”及“必须选择 SOP 才能随访”的设计。

## 本轮业务路径

医院 Mock / 人工补充病历 → 绑定责任团队 → 核对原报告 → 人工安排随访节点和日期 → 起草问询（参考宣教可选）→ 医生审核个体建议 → 按步骤联系 → 未接通记录原因与下次计划，或核实身份后记录实际反馈 → 异常转责任医生 → 完成随访 → 医生接收记录 → 次日复诊核对 → 日归档、周复盘与报告交接。

系统提供业务操作与记录，不提供 SOP 设计器、发布器、规则引擎或培训管理模块。培训使用操作说明。D3/D7/D30/三月/一年只是可选节点名称与日期快捷填写，须工作人员结合原报告确认，不代表已获医院批准的诊疗时间表。没有签字确认的医学阈值不启用自动诊断或预警。

## 验收要求

- 随访无需选择知识条目。可直接用基础问询起草或手工编辑；已发布宣教为可选参考，医学建议仍须责任医生审核。
- 任务可以关联原报告，人工一次安排多个节点，每个节点可追溯至原报告；重复提交不重复建任务。
- 联系记录结构化保存时间、方式、结果、身份核验、报告核对、反馈和凭证。未接通、忙线、号码问题、拒绝联系、身份未核实均不能标记有效随访，必须记录原因及后续处理时间和计划。
- 下次联系时间与原任务截止时间分开保存，重约不能移动完成率分母或掩盖逾期。重复/过期页面提交不能重复生成联系证据。
- 完成随访后进入责任医生的待接收记录，医生确认接收并保存反馈；这是系统内交接，不冒充微信、邮件或短信发送。
- 护士与运营查看自己的应随访、完成、按时完成、逾期和待再次联系任务；主管能看按执行人分组。任务完成率 = 同一截止日期区间的已完成随访任务 / 该区间未取消的随访任务；无分母显示 --。不能用拨号次数作为已完成随访。
- 昨日应复诊而未核实到院的任务单独可查，到院仍需医院事件或人工核验证据，微信点击不是到院证明。
- 日归档与周复盘保存统计快照、问题、改进计划和记录人；周报可打印并记录人工外发凭证，未填写凭证时不得显示已外发。
- 扩充初始化 DML：多科室、多责任团队、各类任务状态、历史与近期任务、全部人工联系结果、异常及复诊结果；全部虚构。重复导入不覆盖用户修改。

## 对其他差距的处理

筛查干预、精细化服务履约、项目活动和转诊仍需独立页面与流程，现有患者列表不等于已实现。产品介绍须明确实现范围，不声称“全病程管理已齐全”或“知识覆盖所有科室”。真实医院、微信身份、扫码入组及患者交互待需求与授权确定；仅有接入配置不算接通。自媒体获客、AI 家庭医生、医保商务不进入本轮研发，待形成可验收规格。
