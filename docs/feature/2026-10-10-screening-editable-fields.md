# 诊前筛查标签、分组与可编辑信息 Implementation Plan

**Goal:** 在危急预警、一张网检出、体检检出、健康筛查四个入口增加标签、分组筛选和统一编辑能力，删除独立高危患者环节。

**Architecture:** 延续现有绿色医疗工作台与原生 HTML/JS 原型。共享 `scRecords` 投影与原始记录，修改后列表、详情、筛选、导出即时一致；所有操作限定可见记录并追加修改前后审计。既有来源报告、实际业务流程和新录入的跟进状态分别保存。

**Tech Stack:** 原生 JavaScript、CSS、Node VM 行为测试、离线 HTML 打包。

## 设计选择

采用每行「编辑信息」弹窗：较逐单元格编辑更适合一并校验责任人员和医学依据；较新增独立维护页面更少跳转。保留现有「详情」「查看与处理」。标签和分组筛选常驻第二行；标签支持逗号分隔的自定义多标签，分组支持已有值建议与自行输入。

运营主管可维护标签、分组、跟进状态、进度说明及责任分配；护士/运营可维护自己负责记录的跟进信息。责任医生本人可修改本次心电分级与患者风险并填写依据。用户的“去掉高危患者环节”解释为删除独立子菜单，风险值与医生处理保留；旧链接转到全部筛查记录的高危/危急筛选。

不把自行录入的跟进进度当作到诊、承接、入组凭证。列表同时显示现有业务阶段；更换责任医生使医学结论待新医生核实。历史台账原始风险不改写，新增医生复核另存。
