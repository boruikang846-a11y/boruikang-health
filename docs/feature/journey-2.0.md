# 全旅程后端与管理端 V2.0 开发与验收说明

版本：2026-10-05。基于现有 Java 21 / Spring Boot 4 / MyBatis / React 18 管理系统增量开发。需求来源为用户提供的患者运营需求与全旅程材料；参考图片用于后台布局，材料中的时间表未作为开发约束。

## 本次落地范围

门诊完整旅程：交接接单 → 诊前咨询 → 实际到院 → 院内服务 → 责任医生核对门诊报告 → 个案计划 → 随访及医生查收 → 复诊结果或医生确认无需复诊 → 满意度记录与结案。

出院完整旅程：交接接单 → 院内服务 → 责任医生核对出院报告 → 出院交接 → 个案计划 → 随访及医生查收 → 复诊结果或医生确认无需复诊 → 满意度记录与结案。

支持 FULL 完整接入和 AFTER_CARE 诊后接入。诊后接入明确记录前置阶段跳过，仍要求核对本次事件报告。“诊中患者管理”和“诊后主动干预管理”归入统一的“诊后主动干预”工作入口。

患者中心保留真实 CSV / XLSX 文件上传、字段校验、去重、事务入库及错误回执。既有患者、病历、任务、预约、实际到院与医院 Mock 接口继续使用。

## 核心业务约束

- 一次就诊或出院对应一个服务旅程；同一患者可保留多次就医历史。来源事件按医院、来源系统、事件键去重。
- 当前负责人本人接单。患者重新分派后，新负责人须重新交接；旧负责人失去患者访问权。
- 临床报告核对、计划审核、随访结果查收和医学异常处置均由当前责任医生本人完成。运营人员不能代签。
- 个案计划保存报告快照、节点及模板版本；审批通过后在同一事务中生成任务。拒绝的计划不生成任务，替换计划取消旧计划未完成任务、保留已完成记录。
- 门诊到院使用实际到院记录。复诊闭环要求本次报告之后的独立复诊到院和已完成预约结果；无需复诊必须由责任医生确认。
- 随访未完成或医生未查收、异常/咨询未闭环时禁止结案。满意度分别保存已评分、拒绝、无反馈、未邀请，不把缺失值当评分。
- 暂停、退出及过期计划禁止继续执行对应任务。退出本次旅程和撤回患者本用途服务授权分开：撤回后停止该患者所有未结束旅程与随访/咨询执行，历史保留。新的明确授权允许创建新旅程，旧旅程不会自动恢复。撤回不代表删除其他医疗用途授权。
- 异常和咨询保留受理、处置、执行回执及逾期记录；退出后未完成的安全事项仍可处置。
- 所有变更使用版本校验和患者/旅程锁；同一请求键及相同操作者、请求内容重试返回原始结果，改动内容或操作者冲突。历史与审计只追加。
- 患者、计划和工单查询在数据库中按当前人员及医院范围过滤；平台管理员不查看患者医疗数据。

## 管理端与接口

管理端提供 `/journeys` 旅程列表、`/journeys/:id` 个案办理页、`/after-care` 主动干预工作台。患者详情可直接查看该患者旅程。工作台提供交接、计划草稿、异常/咨询、逾期统计和筛选。

新增接口统一 POST `/boruikang/admin/journeys/`：

| 接口 | 用途 |
| --- | --- |
| create | 按就诊/出院事件建旅程 |
| query / detail | 旅程列表与完整历史 |
| handoff_accept | 当前负责人接单 |
| step | 前进步骤及记录真实凭据 |
| status | 暂停、恢复、退出、重新交接、撤回授权 |
| plan_draft / plan_review | 个案计划草稿、责任医生审批 |
| case_open / case_action | 异常与咨询建单、受理、处置、回执 |
| no_revisit | 医生确认无需复诊 |
| cases_query / summary | 工单筛选与工作台统计 |

请求采用 snake_case，更新包含 id、version、request_id 和 evidence。Controller、请求/响应 DTO 和业务服务均随源码交付。

数据库新增七张表：service_journey、journey_result、journey_command、journey_plan、journey_task_link、journey_case、service_consent_withdrawal。MySQL 8 增量脚本独立交付，不覆盖原表与数据。生产执行前应在医院测试数据库备份、审查和演练；本次未执行生产升级。
