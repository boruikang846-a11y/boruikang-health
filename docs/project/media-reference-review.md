## 需要区分的宣传与待确认需求

1. 图片和视频出现倍数增长、到院率、满意度、低成本及分钟级响应等宣传数字。本轮没有原始统计、机构授权和归因口径；不放入产品 KPI、种子数据或用户承诺。
2. 部分素材强调“门诊增量是唯一指标”，另一些强调过程服务和患者体验。这是资料内部需要取舍的经营观点。本期仍展示服务完成、按时履约、异常闭环与有证据的到院，经营增量指标需另外定义基线、归因窗口和口径。
3. “AI 自动解读病历、自动制定随访、精准营销和全量患者画像”等内容属于方案设想。没有据此增加自动诊断、调药、患者自动回复或营销能力。
4. 图中具体病种节点、处置时点及症状示例不直接转成临床规则。任务日期以人工确认的原记录和本院已审核 SOP 为准。
5. HIS、企业微信、身份打通与私有模型等部署表述只记录为参考，未验证其在 HEALTH 开发环境可用。

## 后续优先评审的问题

- 医生是否需要在一个摘要里查看待审核、已升级问题、复诊意向与本周服务结果；明确这些信息来自哪条记录。
- 如何区分联系尝试、成功沟通、患者反馈和业务完成；如何记录无法联系原因及下一次计划。
- 医院确定服务时间、接待范围和升级负责人后，再确定响应时效与提醒方式。
- 患者端需求确认时，分别定义企业微信、小程序、Web 的职责、授权、身份与数据展示，避免先做三套重复功能。

这些是供后续评审的候选项，不属于当前 MVP 已实现功能。本轮增补参考记录，未扩大患者端功能范围。
