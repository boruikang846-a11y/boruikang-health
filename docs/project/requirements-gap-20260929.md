# bgssai-health 需求对照与差距报告

日期：2026-09-29。依据：桌面《慢病管理系统资料》全量（281 份文档提取文本、约 330 张截图/流程图、16 份 PPT 内嵌图、12 段视频抽帧）与 `reference-prototypes/aecg-doctor-captures`（AECG 云医生工作站 52 张），对照 `develop`（d9aaff2，MVP 1.4）的页面、接口、服务与 DDL 逐项核对。本文只回答两件事：这批资料要的是什么系统；现在的系统哪里不满足。

## 一、资料吸收结论：这批资料要的到底是什么产品

### 1. 业务模式（所有医院方案、汇报、合同反复出现的同一条主线）

```
基层心电设备（心电一张网）/ 体检 / 公卫 / 门诊 / 出院
  → AI 判读 + 医生复核 → 危急预警 / 高危检出 / 中低危
  → 驻院运营专人电话邀约（三次沟通：建立信任→种草跟进→关怀反馈）
  → 上转 / 绿色通道预约 → 到院 → 检查 → 确诊 → 治疗/住院 → 出院
  → 入组（病种路径 / 服务包）→ D3/D7/D30/M3/M6/M12 随访
  → 指标采集 / 异常预警 / 医生升级 → 复诊复查回流 → 服务包续约/升级
  → 日报 / 周报 / 月报 / 院长汇报
```

- 执行主体是我方驻院运营团队（南京心康），医生只做三件事：识别患者、一句话推荐、异常时医学决策。这与 1.4 已定的"托管运营、医生不登录后台"一致。
- 业务范围不是单一心血管：资料里已有心血管（房颤/PCI/心衰/高血压）、脑卒中（漳州）、检后三高（济宁）、中医治未病（南京中医院）、医美/康复、糖尿病、减重，用户此前也已明确"所有科室"。
- 患者来源明确分层：心电一张网筛查、体检检出、公卫、社区/基层上转、医院门诊、住院/出院、活动/义诊、医生码。每个来源都要能追溯到机构（分院/社区/村站）。

### 3. 运营执行口径（决定报表和任务字段的真正来源）

- 《患者运营执行表格 V1.1》：回访邀约跟踪表一患者一行，字段含风险分层（危急/高危/中危/低危）、来源渠道、运营负责人、**当前状态（P7-管理中 / P8-待复诊复查 / P9-暂缓拒绝 / P11-转外院管理 …）**、三次沟通记录、预约日期/科室医生、到诊日期/到诊状态/有效到诊/未到诊原因、下次随访日期、距下次随访天数、超期状态。昆中 7 月真实台账就是按这张表在跑。
- **10 项核心指标**（周汇总/月统计/绩效表共用）：应管理人数、有效触达率≥95%、高风险及时处理率≥95%、预约率≥60%、预约履约率≥50%、有效到诊率≥50%、入组率≥40%、随访完成率≥90%、复诊/复查完成率≥75%、失访率≤5%。
- 《日常电话随访工作参考》：首次触达→到诊提醒→就诊后 1–3 天回访→复诊提醒→失约回访→定期随访→失联升级（2 短信+3 电话无回复→家属/社区转告）；未接通必须发短信并记台账；高危 24 小时内首触达、危急立即上报；拒绝就诊需记录并告知风险后确认。
- 《驻院运营人员执行培训资料及经营表》：每日四件事（新增入组/患者活跃/预约到院/经营数据），六张经营表（月度患者运营与转化、收入成本净收益、患者池分层、日执行、周复盘、成本），周一目标/周三检查/周五复盘。
- 绩效表：运营人员 800 元基数按触达及时率/数据准确率/随访完成率/预约执行/有效到诊/到诊率/检查转化/门诊住院转化/入组/复诊分项计算；负责人 2000 元基数六项。绩效数据来源写明"回访邀约跟踪表、10 项指标统计表、周汇总表"——即系统必须能自动出这些数。
- 玉环双入口表单包：纳入登记表（病种/分层/来源场景/推荐医生/是否签约）、随访计划与执行记录表、异常升级处理单、周推进复盘表、每日清单、月度指标汇总；基层上转流程表（分级→处置时限→接诊路径→总院反馈闭环）。
- 周报模板：3 个运营指标（入组、随访完成率、预警闭环率）+ 1 个经济指标（复诊回流人次或检查检验增量）+ 里程碑 + 下周三件事。

### 6. 老板在资料里反复强调的口径（134 份医院方案 + 79 份经营文档 + 12 段视频的共同点）

- 卖的不是设备不是系统，是"患者管理能力/结果"；检查费是小账，患者池、到诊、复诊、服务包是大账。
- 医生只做三件事：识别患者、一句话推荐、异常决策；"医生不做运营、运营不碰诊疗"；AI 只出草稿永不直发患者。
- 每条异常数据都要有下一步动作、责任人、时限、结果回流；"没有记录等于没发生"；台账三问"从哪来、到哪步、下次何时"。
- 数据真实、口径统一：项次≠人数、跨表不相加、去重后统计、报表必须写清分子分母；数据造假一票否决。
- 先跑通闭环再追规模：90 天试点、1 科室 + 1 入口 + 1 病种；"不要等系统完美再启动，先 Excel 台账也要跑业务"。
- 到诊率是核心考核（井研修订版锁定 10%：3,600/36,000，分母是"完成授权的目标人群"），看板每天盯触达率/预约率/到诊率。
- 医院是唯一收费主体；第三方不碰医保结算；服务包必须明示告知、留痕、可导出验收。
- 患者端应是独立 APP 不依赖微信小程序（《产品设计原则》）——与当前"企微/小程序/Web 三模式"介绍口径不一致，见第四节拍板项。

### 7. 用户此前已定、本轮资料未推翻的边界

AI 给意见人负责回答；全科室而非仅心血管；患者端只做介绍；医生/护士不登录后台，我方运营登记院方回执；不启用未签字的临床阈值。

关于分成：用户 08-28 口头定"比例提成不可行、本期不做分成结算"。但资料里分成/提成方案大量并存（心电费 60/40、服务包 40/40/20、双利润池、销售三段式、代理佣金），且同一医院不同版本口径不同；犍为/行唐则写明"三不"（不按例计费、不按收入分成、不设挂钩条款）。本报告按用户口径处理：系统**记录**服务包 SKU、订单与履约证据，**不做**分成结算引擎。

## 二、当前系统实际能做什么（develop d9aaff2）

一句话：现在是一个"随访任务的起草→登记院方审核→人工联系→登记交接"的**记录工具**，覆盖 PRD 的 G01 随访任务、H 预警的人工版、I 复诊的人工版和 J 驾驶舱的一小角。

| 模块 | 已实现 |
| --- | --- |
| 账号 | MANAGER / OPERATOR / PLATFORM_ADMIN 登录；院方医生只是联系人表 `hospital_clinician` |
| 工作台 | 在管/待执行/待处理异常/逾期 4 张卡、近 7 日应随访/已完成柱图、优先待办 6 条 |
| 患者中心 | 关键字/风险/科室三个筛选；建档（姓名/电话/性别/年龄/科室/病种/医生/负责人/备注）；详情四个 Tab（就诊记录、任务、沟通记录、审计）；管理档案（医生、负责人、生命周期 4 态、风险 5 级+依据、服务包、备注） |
| 就诊记录 | 门诊/出院/体检三类，摘要+用药周期+复诊日期+四个指标；保存后自动建"次日核对报告"待办和复诊任务 |
| 随访/咨询任务 | PENDING→IN_PROGRESS→PENDING_REVIEW→APPROVED→CONTACTED→COMPLETED；模板/AI/手工起草；登记院方审核（渠道/时间/凭证）；结构化联系记录（接通：身份核实、报告核对、用药反馈、患者问题；未接通：原因、下次时间、下次计划）；完成后交接院方并登记反馈；批量安排 ENROLLMENT/D3/D7/D30/M3/Y1 节点 |
| 异常任务 | PENDING→IN_PROGRESS→ESCALATED→COMPLETED，关闭需院方处置凭证 |
| 复诊任务 | PENDING→BOOKED→ARRIVED→COMPLETED / NO_SHOW / CANCELLED，预约与到院各填一段证据文本 |
| 宣教与服务包 | 知识条目两类（EDUCATION / PACKAGE），草稿→登记院方审核→发布；服务包只有周期天数与随访次数两个参数 |
| 渠道 | 名称/来源/科室/医生/负责人，二维码只打开介绍页 |
| 报表 | 任意区间：随访完成率、按时率、异常闭环率、复诊到院率；按运营人员和按医生两张表；日归档/周复盘快照与人工外发凭证 |
| 医院数据 | Mock 适配器，2 位患者 3 份报告，幂等同步 |
| 接入 | AI（TokenHub）配置；企微/公众号/HIS/周报投递均为"未接入"占位 |
| 患者端 | 纯介绍页，中英文 |

## 三、差距矩阵（按目标系统的模块逐项对照）

优先级：**P0** = 资料里运营团队现在就在纸上/Excel 里天天做、系统不做就无法替代台账；**P1** = 对标系统和 PRD 的核心闭环；**P2** = 依赖外部接口或用户尚未拍板。

## 四、需要用户拍板的六件事

1. **PRD V1.0 与 1.4 边界的冲突**：PRD（09-28）要 AI 随访 Agent 直接与患者对话、扫码入组、企微、患者小程序、医生工作台。1.4 定的是"AI 只出草稿、患者端只介绍、医生不登录"。下一版按哪个走？建议：后台先补齐 A/B/C/D/F/H 的 P0 项（都是运营团队今天在 Excel 里做的事），AI 对话与患者端等医院授权后再开。
2. **状态口径**：患者状态用 PRD 的 S00–S90 还是运营台账的 P7/P8/P9/P11？建议系统内用完整状态，报表映射到台账口径。
3. **服务包是否记价格与订单**：资料里 SKU 都带价格和对账字段，用户此前定"不做分成结算"。建议记录 SKU 价格与签约/到期，不做支付。
4. **心电一张网/体检数据接入方式**：接口、Excel 导入还是人工录入？影响 A1/A4/A5 的做法。建议先 Excel 导入 + 人工录入，接口字段按华信文档预留。
5. **短信/企微通道**：先做"人工已发"登记还是直接接短信网关？建议先登记 + 模板库。
6. **机构维度**：是否现在就引入分院/社区/村站（医共体上转必需）？建议引入，单院也能用。
7. **患者端形态**：《产品设计原则》写"独立 APP 不依赖微信小程序"，当前介绍页和 PRD 写企微/小程序/Web。下一版介绍页和后续开发按哪个口径？
