# 正式后端与患者上传开发说明 V1.4

本次在现有 Java 21 / Spring Boot 4.1 / MyBatis 后端与 React 管理端上完成患者文件上传功能。截图用于深色导航、绿色操作、白色内容卡片与列表布局参考，没有复制截图中的患者数据。

## 交付范围

- 正式管理端患者中心：下载 Excel 模板、文件选择、预览、字段校验、医生/负责人/类型/来源分派、确认、批次结果。
- 新增 POST `/bgssai/admin/patients/import_file`，multipart/form-data：`file` 为原始 .xlsx/.csv；`settings` 为 application/json 部分，字段使用 snake_case。
- 服务端重新解析文件，不信任浏览器预览结果。整份文件解析和字段校验通过后才调用事务导入；任一错误阻止整批。
- 5 MiB / 500 条 / 64 列限制，拒绝旧 .xls、公式、错误单元格、损坏文件及重复字段表头；UTF-8 CSV 与 GB18030 CSV，XLSX 首个非空工作表。电话、编号按文本填写可保留前导零。
- 必填：姓名、年龄（0–130 整数）、联系电话、科室、病种/管理原因；选填：性别、来源编号、证件号、出生日期、地址、紧急联系人/电话、住院号、床号、内部备注。
- 按医院隔离，运营主管/护士/运营人员可导入；非主管只能分配给自己；医生/平台管理员不能上传。原 JSON 导入接口保留兼容。
- 来源编号或证件号重复跳过，已有档案不覆盖。无去重标识时，同一批次重试防重，跨批次不能保证去重。不按共享电话合并患者。
- 档案和审计持久化，首次联系待办可选、截止由正式后端 SLA 配置生成。上传不等于完成知情同意、医生审核或服务激活。
- 原始文件不另行归档；业务字段写入数据库，日志只记录批次、数量及异常类型。

`settings` 示例：
```json
{"import_batch":"file-20261005-001","doctor_id":2,"owner_id":3,"patient_type":"DISCHARGED","source_scene":"DISCHARGE","outreach":true}
```
责任医生、负责人和机构使用当前医院有效 ID，示例 ID 仅对应本地虚构演示账号。

## 本地运行

交付 JAR 已包含正式 React 管理端。安装 Java 21 后，在选定的数据目录运行：
```sh
java -jar /绝对路径/博瑞康患者管理后端V1.4.jar --spring.profiles.active=local
```
打开 `http://127.0.0.1:8080`，进入患者中心。默认本地演示主管账号 `manager`，密码 `HealthDemo@2026!`。本地 H2 数据库写入启动目录下 `.local-data/health`；重启后保留。仅供本机开发验收，包含虚构演示数据和开发配置。

前端同时提供 pnpm-lock.yaml；本次使用 pnpm 安装和构建。使用 pnpm 时可执行 `pnpm install --frozen-lockfile`、`pnpm test`、`pnpm run build:deploy`。

源码构建：根目录 `mvn test`；管理端前端目录 `npm ci`、`npm test`、`npm run build:deploy`；再于根目录 `mvn -pl bgssai-health-admin/bgssai-health-admin -am package`。数据库表结构沿用现有 SQL，本功能不新增业务表。

## 原型与正式系统的区别

`博瑞康全周期管理原型.html` 同步更新深色导航、绿色操作和患者分类入口，适合讨论全旅程流程。离线原型仍使用页面内演示数据，不连接正式后端。正式患者上传请使用 JAR 中的管理端。

## 验收与边界

- Java 全套：103 项，86 项通过，17 项 MySQL 专项因未配置测试数据库而跳过；无失败。
- 新增真实 HTTP 上传测试 4 项：CSV/Excel 入库、前导零、同批重试、权限、错误行整批拒绝、公式/格式/超限拒绝。
- 前端 12 项导入测试通过，Vite 正式构建通过；离线原型角色/路由和文件导入模型检查通过。
- 当前浏览器环境不能执行本地文件视觉验收；没有宣称像素级还原或完成浏览器点击上传验收。
- 尚未部署医院服务器，尚未进行真实 MySQL、企业微信或 HIS 联调。完整门诊/出院旅程中新增的原型步骤不能视为全部已经后端化。
- 医院上线需用生产数据库配置、独立账号/密钥、HTTPS、数据备份和实际院方验收；演示账号及 local 配置不能用于公网服务。部署仍按仓库要求由独立部署工作流执行。
