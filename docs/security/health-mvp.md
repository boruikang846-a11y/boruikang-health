# HEALTH-MVP-1 开发试点安全边界

> 本文部分角色与 SOP 描述为历史 1.2 设计。当前管理端只允许我方 MANAGER/OPERATOR 及接入配置用 PLATFORM_ADMIN 登录；院方医生/护士不登录，实际审核和反馈凭证由运营人员登记，见 [1.4 托管运营契约](../api/managed-operations-1.4.md)。当前无患者业务入口。

开发期沿用骨架明文存库规范：账号口令、会话 ID、业务 API Key 明文。JWT 仍签名，服务端校验会话、角色、医院和患者归属，审计只追加。此口径仅适用于虚构数据的开发联调，不等于可直接生产使用。生产前须确定口令哈希、密钥管理、访问审计、医院授权与隐私告知等正式方案。

患者业务接口当前未开放，不凭手机号认领已存在病历。渠道 token 随机不可枚举；链接没有患者个人信息。PLATFORM_ADMIN 不获得临床数据。后台患者和任务按医院、运营负责人隔离；院方医生/护士没有后台令牌。临床建议和宣教内容先由院方在线下审核，我方登记实际审核凭证后才可继续；登记者、院方联系人、时间和证据分别留痕，不将运营登记当成医生电子签名。角色/身份不可由请求体提升。

AI 默认关闭；启用时仅辅助准备草稿，不得直接产生医嘱或对患者发信。正式 SOP 尚未取得，SOP 是系统外的业务使用流程，不是可发布知识条目。外部调用需显式启用并通过端点白名单；API Key 不返回前端、不输出日志。

开发域名对公网发布前应启用 HTTPS、访问控制并更换演示口令。MVP 数据只用虚构样本。证书、账号密钥和医院渠道凭证的部署状态必须如实记录，不能把配置模板当作线上已执行。

本轮范围调整：患者公开介绍不暴露任何患者业务 API，不采集个人数据。人工触达记录只记事实与证据，不做外部自动发信。当前 GitHub 仓库为公开仓库，开发环境数据库凭据与 JWT 密钥不提交，profile 保留空值并在部署前由受控 Jenkins 工作区填入。
