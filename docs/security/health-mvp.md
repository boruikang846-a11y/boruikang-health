# HEALTH-MVP-1 开发试点安全边界

> 1.6 起管理端允许 MANAGER、OPERATOR、NURSE、DOCTOR 与接入配置用 PLATFORM_ADMIN 登录，见 [1.6 契约](../api/clinical-login-1.6.md)。医生只能看到并处理自己负责的患者；审核、查收、异常处置只能由责任医生本人执行；护士与运营人员只处理分配给自己的患者。当前无患者业务入口。

开发期沿用骨架明文存库规范：账号口令、会话 ID、业务 API Key 明文。JWT 仍签名，服务端校验会话、角色、医院和患者归属，审计只追加。此口径仅适用于虚构数据的开发联调，不等于可直接生产使用。生产前须确定口令哈希、密钥管理、访问审计、医院授权与隐私告知等正式方案。

患者业务接口当前未开放，不凭手机号认领已存在病历。渠道 token 随机不可枚举；链接没有患者个人信息。PLATFORM_ADMIN 不获得临床数据。后台患者和任务按医院、负责人与责任医生隔离。临床建议和宣教内容由医生本人登录审核，审核人与时间由会话写入，不接受请求体传入；系统内审核不等于电子签名或 CA 认证。医护账号由运营主管开通，停用或重置密码立即结束该账号登录。角色/身份不可由请求体提升。

**真实医院上线前必核**：医护账号口令目前按开发期规范明文存储（与骨架一致），只能用于虚构数据环境。接入真实医院医生、护士前，必须先定口令存储方案（哈希）、首次登录强制改密、账号开通与离职停用流程、医院对医生在系统内审核的授权说明。

AI 默认关闭。运营主管或平台管理员在接入设置填写 DeepSeek API Key 并启用后，工作人员点击「根据病历生成随访建议」时，系统把该任务关联的出院小结或病历正文、用药周期、复诊日期和医生已写意见发给白名单中的接口，不附带患者姓名和电话。生成结果只是草稿，责任医生审核通过后才能人工联系；AI 不向患者发信。调用失败不保存草稿。API Key 不返回前端、不写入日志。端点仅允许 DeepSeek 官方接口；存量其他端点的密钥不得沿用，须重新填写 DeepSeek API Key。正式 SOP 尚未取得，SOP 是系统外的业务使用流程，不是可发布知识条目。

开发域名对公网发布前应启用 HTTPS、访问控制并更换演示口令。MVP 数据只用虚构样本。证书、账号密钥和医院渠道凭证的部署状态必须如实记录，不能把配置模板当作线上已执行。

患者公开介绍不暴露任何患者业务 API，不采集个人数据。人工触达记录只记事实与证据。1.9 起系统可以经企业微信、公众号发消息，但只在工作人员点击时发出，没有定时或自动发信，见下节。当前 GitHub 仓库为公开仓库，开发环境数据库凭据与 JWT 密钥不提交，profile 保留空值并在部署前由受控 Jenkins 工作区填入。

## 1.9 企业微信与公众号

**凭证**：企业 ID / AppID、Secret、回调 Token、EncodingAESKey 按开发期口径明文存 `integration_config`，只写不回显，不进日志和审计正文；access_token 只在进程内存。真实医院上线前须与口令方案一起确定密钥存储与轮换。仓库、种子和文档里不得出现真实凭证；dev 种子只有标明模拟的占位值，且不含回调 Token。

**回调**：`/boruikang/open/**` 不需要登录，是唯一对微信服务器开放的入口。通道未启用、没有回调 Token（企业微信还须 AESKey）或签名不符一律 403，不落任何数据；密文还要核对接收方 corp id / app id。签名比较用常数时间。XML 禁用 DTD 与外部实体，请求体限 64 KiB，按来源 IP 限流。未校验时间戳新鲜度，重放由事件幂等键抵消。

**出站**：微信主机固定为官方域名，不能在页面配置，避免把服务器当跳板。URL 模板不含凭证，日志不输出 URL、凭证和消息正文。

**身份**：微信好友、粉丝与患者档案由工作人员核实后人工绑定，不按手机号、昵称、UnionID 自动合并。未绑定的联系人只有运营角色可见；绑定后按患者归属隔离，医生只读自己患者的记录，平台管理员看不到联系人和消息。

**内容**：临床内容仍须责任医生本人审核。"已审核正文"由服务端从任务读取，不接受页面传入；自由文字只用于服务提醒和事务答复，页面有提示并全部留痕，但系统无法识别文字是否含医学建议，这一条靠运营流程约束。企业微信未开通会话存档，成员与患者在企业微信里的聊天正文不进系统。

**模拟通道**：只在 local、test、dev 可选，prod 配置为不允许且代码再按 profile 拦一次。模拟记录带标记，模拟与真实联系人不能混用通道。模拟不代表已接通。

**真实医院上线前必核**：医院企业微信与公众号的主体认证、客户联系权限、可信 IP / IP 白名单、模板消息类目与模板审核；向患者告知由受托团队提供服务及会话处理方式；回调域名的 HTTPS 与备案。
